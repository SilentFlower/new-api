# 渠道级视觉辅助识别

## 目标

为不具备视觉能力、但需要处理图片输入的目标渠道提供渠道级“视觉辅助识别”能力：当客户端向 OpenAI 兼容 `/v1/chat/completions` 或 Claude `/v1/messages` 发送含图片请求时，new-api 可先调用配置的视觉模型生成图片描述，再把原请求改写为目标渠道可处理的文本请求。

该能力必须绑定目标渠道配置，并且按该渠道 `model_mapping` 链式重定向后的最终上游模型判断是否触发，而不是按用户请求中的原始模型判断。

## 需求

- 支持范围：
  - OpenAI 兼容 `/v1/chat/completions` 的 `messages[].content[].image_url`。
  - Claude `/v1/messages` 的 `messages[].content[]` 图片内容块。
- 渠道级配置：
  - 配置挂在目标渠道 `setting` 中，不做全局强制开关。
  - 目标渠道可配置是否开启、辅助渠道 ID、辅助模型、辅助提示词、目标模型匹配列表、缓存 TTL、失败策略、是否移除原始图片。
  - 目标模型匹配必须基于 `info.UpstreamModelName`，即渠道 `model_mapping` 链式重定向后的最终模型。
- 请求预处理时机：
  - 必须在主请求 token 估算、敏感词检查和预扣费之前完成视觉辅助改写，确保后续计费和检查看到的是实际发给目标模型的请求形态。
  - 现有 `TextHelper` / `ClaudeHelper` 中的模型映射逻辑需要保持幂等，避免重复映射和重复辅助。
- 改写行为：
  - 视觉辅助结果以中性的图片内容文本块写回原请求，不向目标文本模型暴露“辅助识别”等实现细节。
  - 是否保留原图片由渠道配置控制；面向非视觉目标渠道时推荐移除原图片。
  - 不改变用户原始意图文本、工具参数、采样参数等与图片辅助无关的字段。
- 缓存与重复请求：
  - 对同一图片、同一辅助渠道、同一辅助模型、同一辅助提示词和同一图片细节配置生成稳定缓存 key。
  - 同一请求内重复图片必须复用结果。
  - 客户端下一轮继续提交原始图片历史时，应命中缓存，不应重复调用视觉模型。
  - 缓存值存图片描述和必要元信息，不保存原始图片正文。
- 防循环：
  - 内部视觉辅助调用必须带有上下文标记，禁止再次触发视觉辅助。
  - 辅助渠道即使也开启视觉辅助，也不能递归调用。
- 计费与日志：
  - 主请求按改写后的请求继续走现有计费流程。
  - 辅助视觉调用按实际使用的 `assist_channel_id` 与 `assist_model` 单独向用户扣费，并作为独立的视觉辅助消耗记录。
  - 日志或管理可观测信息中应能区分是否触发视觉辅助、辅助渠道、辅助模型、缓存命中情况和失败原因。
- 兼容性：
  - 不影响未开启视觉辅助的渠道。
  - 不影响纯文本请求。
  - 不影响全局或渠道的透传模式；开启透传时默认不做请求改写。
  - 保持 SQLite、MySQL、PostgreSQL 兼容；本任务优先复用渠道 `setting` JSON，避免新增数据库表。

## 验收标准

- [ ] 目标渠道开启视觉辅助后，OpenAI 兼容含图片请求会先经辅助视觉模型识别，再以文本形式发送到目标渠道。
- [ ] 目标渠道开启视觉辅助后，Claude `/v1/messages` 含图片请求具备同等行为。
- [ ] 视觉辅助触发判断使用 `model_mapping` 链式重定向后的 `UpstreamModelName`。
- [ ] 未开启视觉辅助、纯文本请求、透传请求保持现有行为。
- [ ] 同一图片重复出现或跨轮次重复提交时命中缓存，不重复调用辅助视觉模型。
- [ ] 辅助调用不会递归触发视觉辅助。
- [ ] 主请求 token 估算和预扣费基于改写后的请求。
- [ ] 辅助视觉调用按辅助模型实际消耗单独扣费，并能在日志中识别为视觉辅助消耗。
- [ ] 有单元测试覆盖 OpenAI 请求提取/改写、Claude 请求提取/改写、重定向后模型匹配、缓存 key 和防循环。

## 已确认依据

- OpenAI 兼容聊天请求由 `dto.GeneralOpenAIRequest` 表示，图片内容块类型为 `image_url`。
- Claude 原生请求由 `dto.ClaudeRequest` 表示，`/v1/messages` 路由走 Claude relay 格式。
- 现有 `ModelMappedHelper` 支持链式 `model_mapping`，最终写入 `info.UpstreamModelName` 并调用 `request.SetModelName`。
- 当前 `controller.Relay` 在进入具体 `TextHelper` / `ClaudeHelper` 之前就会做 token 估算和预扣费，因此视觉辅助如需影响主请求计费，必须前移到 controller 层或其下方的统一预处理阶段。

## 已确认决策

- 辅助视觉调用按它实际使用的 `assist_model` 和 `assist_channel_id` 单独扣费，并在日志中标记为 `vision_assist`。
