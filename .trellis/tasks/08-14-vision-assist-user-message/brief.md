# Brief — 视觉辅助引入用户原始问题

## Goal

- 让视觉辅助模型结合当前用户原始问题分析图片，优先产出回答人物身份、OCR、表格、属性和关系问题所需的信息，而不是仅返回通用图片描述。

## Scope

- 从 OpenAI Chat、Claude Messages 和 OpenAI Responses 请求中解析最新的非空用户文本。
- 最新用户消息没有文本时向前回溯最近一条非空用户文本；完全没有用户文本时保持现有通用识图行为。
- 渠道可在逐张识别和同消息多图合并识别之间切换；新建渠道默认合并识别，历史缺省配置仍按逐张识别。
- 合并模式让同一原始消息中的多张图片进入一次辅助请求，不跨消息合并，综合结果只写回一次。
- 在现有单条 `role = "user"` 辅助多模态消息中依次加入渠道识图规则、明确分隔的用户原始问题和图片。
- 优化内置默认提示词，使识图结果围绕用户问题，并对人物身份等不确定判断保留限定语。
- 将用户文本哈希、多图模式和有序图片组加入视觉辅助缓存键，避免跨模式或跨图片组串用。
- 将下游注入说明调整为中性的“与当前用户问题相关的图片信息”，同时保留原始用户问题和现有 `strip_image` 行为。
- 为用户文本解析、请求构造、缓存隔离、写回语义和跨协议边界增加回归测试。

## Non-Goals

- 不新增提示词模板变量，不自动判断用户问题是否需要多图联合分析。
- 不改变辅助调用计费、重试、失败策略、端点选择和图片移除配置。
- 不引入多轮摘要、语义检索、第二阶段识图或新的模型调用链。
- 不实现人物身份数据库或专门的人脸识别能力。

## Key Decisions

- 用户意图采用请求中最新的非空用户文本，只读取用户角色内容，不复制 system、assistant、tool 或工具输出历史。
- 渠道 `vision_assist.prompt` 继续作为稳定识图规则，用户原始问题由后端自动追加，不依赖管理员配置占位符。
- 内部辅助请求继续保持单条 `user` 多模态消息，避免破坏 OpenAI Chat、Responses、Anthropic Messages 和 Gemini Native 转换契约。
- 新建渠道表单默认选择 `combined`；历史渠道缺失或配置非法时归一化为 `separate`，管理员仍可手动切换。
- 用户问题和多图模式会改变识图结果，因此缓存键必须包含规范化用户文本、多图模式和有序图片组的哈希；缓存值和日志不保存用户原文。
- 实现扩展到视觉辅助 Service、Relay 响应映射、relaykit 设置 DTO 和渠道表单，不修改 Controller 或渠道适配器。

## Key Context

- 当前默认提示词、辅助请求构造、缓存键和下游写回均位于 `service/vision_assist.go`。
- `dto.Message.ParseContent()` 和 Claude 现有内容解析方法可读取字符串及多模态文本块，不需要修改 `relaykit/dto`。
- OpenAI Responses 的 `Input` 是原始 JSON，必须使用 `common.Unmarshal`，并区分普通用户消息与 `function_call_output` / `custom_tool_call_output`。
- 相关执行契约来自 `.trellis/spec/backend/relay-vision-assist.md`，build 分支改动遵循最小冲突面原则。

## Risks / Deferred

- Responses 工具输出文本若被误识别为用户问题，会污染识图意图，必须有直接回归测试。
- 缓存键算法变化会产生一次自然冷启动，旧缓存按现有 TTL 过期，不做迁移。
- 人物身份输出仍受辅助视觉模型能力限制；本任务只要求可靠时给出可能结论并保留不确定性。

## Acceptance

- OpenAI Chat 图片问题“这个人物是谁？”会把该问题和图片一同发送给辅助模型，且内部请求仍只有一条 user 消息。
- Claude 字符串/多模态文本和 Responses 普通用户消息都能正确提供用户意图，工具输出文本不会被误用。
- 最新图片消息无文本时能回溯最近用户问题；没有任何用户文本时保持现有行为。
- 同图同问题命中缓存，同图不同问题不复用旧结果，用户原文不进入缓存值或日志。
- 逐张模式保持历史调用方式；合并模式对同一消息内多张图片只调用一次并只写回一段综合结果。
- 新建渠道默认合并识别；历史渠道缺省或非法配置仍保持逐张识别。
- 渠道表单可读取、切换和保存多图模式，七语言文案完整。
- 写回结果使用“图片相关信息”中性表述，保留不确定性且不改写原始用户问题。
- 现有 Chat、Responses、Claude 和各视觉辅助端点回归测试继续通过。
- `go test ./service ./relay -count=1`、`relaykit` 独立构建、前端 typecheck/build、最终 `go test ./... -count=1` 和 `git diff --check` 通过。
