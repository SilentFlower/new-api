# 主线集成设计

## 分支与合并

保留两侧历史，在当前工作目录向 build-main 合入固定上游提交。工作区原有改动在规划时与上游变更的同路径交集为空，实际合并前再次核对。路由、协议、权限、计费和数据层共享同一个候选版本及验收记录。

| 入口 | 集成方式 | 观察点 |
|---|---|---|
| Relay 路由及渠道分发 | 沿用主线插件入口，接回 Claude 上游计数、Compact 原始载荷、模型快照、识图和渠道搜索。HTTP/2 PING 采用主线已有实现。 | 路由只注册一次，上游请求、插件调用和财务副作用与实际调用一致。 |
| Responses WebSocket | 在新版每轮处理生命周期接回本地首帧期限、重连、取消、并发租约和 Compact。分清 SSE、JSON 和上游 HTTP/2 保活。 | 轮间并发归零，开流后不重放已交付内容，重试及逐轮账务可追踪。 |
| relaykit DTO 及转换注册 | 保留主线转换和工具处理，接回 Claude 续轮上下文、Read 提示及 diagnostics、fallbacks、thread 字段，保留客户端显式零值。 | 分别核对原生协议和经转换协议，多轮前缀稳定。 |
| 计费、预算和权限 | 合并钱包上限与本地周期预算上限的独立语义。保留计费模型快照、任务重试查价、订阅及钱包退款。按现有角色为新式 PAT 声明所需权限。 | 用请求 ID 对上钱包、令牌、渠道、预算及消费日志。超管操作、个人访问令牌与模型 Key 分别测试。 |
| 任务插件、审计与历史记录 | 在新 Google/Vertex 任务出站、取消、轮询、下载入口接回渠道限制。继续处理历史任务、消息审计队列与工作流旧数据。 | 旧数据可读，重启可重入，用户和任务归属一致。 |
| 统计及界面 | 并行维护旧名称维度、新 ID 维度、缓存差量和新增缓存列。保留 Excel 依赖和主线 CSV。用目标路由生成器重建页面，用双亲键并集核对七语言。 | 重复缓存统计、同名 Key、渠道表单字段丢失和入口失联均有回归。 |

## 跨版本迁移

先检查 MySQL/PostgreSQL 钱包四列及运行架构，再启动副本。逐个在用视频模型配对旧价格与插件或普通渠道的新价格。验证新式 PAT 的权限及旧 PAT 的持久化到期点。Telegram 登录按实际启用情况验证新回调。敏感词过滤同时验迁入实例的开关、HTTP 400 与旧版本恢复。多节点共享 Redis 时采用隔离环境预演，生产切换遵循节点同版。各项来源和其他需告知用户的变化见 `research/upstream-upgrade-notices.md`。

## 证据与恢复

以 research 中的冲突清单及编译、行为回归为初始样本。对两侧同时修改且自动合并的文件也做审查，例如 `common/constants.go`。对 13 个冲突 Go 测试文件中的 48 个同路径定制侧独有测试名，逐项保留用例或建立等价断言。

使用隔离的数据库及 Redis 夹具对照升级前后数据，区分程序回退、预算策略版本回退与历史统计补差。另行记录主线可选 ClickHouse 日志库在启用场景下的适用性。

## 已确认的失败轮次账务

普通 Responses WebSocket 沿用 build-bak 的失败退款规则。固定价格 0.002 的请求收到 response.created 后以 response.failed 结束，退回本轮预扣。该场景在上游测试中结算 1000 额度。成功轮次按实际适用的价格结算，HTTP SSE 继续单独验收。

## 已确认的阶梯文本预扣

采用主线的输入费用预扣，默认倍率为 1。以 1,000 个输入 token、缺省输出上限、表达式 `p * 3 + c * 15` 和默认组为例，旧版预扣 62,940 额度，候选版预扣 1,500 额度。显式指定 100 个输出 token 时，旧版预扣 2,250 额度，候选版预扣 1,500 额度。最终按实际用量结算。低余额用户的准入和最高预留金额随之变化。
