# 在 build-main 融合上游主线

## Goal

升级网关主线，让现有调用方继续使用原有转发、计费、预算、令牌、审计和报表功能。

## Background

工作目录为 `/root/project/new-api`，实施分支为 `build-main`。定制基线为 `build-bak@accb26db30bc5b4e8f7e81a877ebbc415f74d1d9`，共同祖先为 `v1.0.0-rc.24`。目标固定为 `81c1fd20efade39a5d5692c8018dfef4cfb30e1d`，比官方 `v1.0.0-rc.51` 标签（`c9c6da278`）多 34 个提交，目标自身尚无发行标签。

试合并材料在 `research/assessment.md` 和 `research/conflicts.csv`。153 个冲突路径和临时副本的 223 个 relaykit 测试用例用于指导正式集成，最终验收以候选代码实测为准。

官方 rc.25 至 rc.51 的 27 份发布说明及标签后 34 个提交已核对，适用条件、代码依据、迁移及回滚动作见 `research/upstream-upgrade-notices.md`。

## Requirements

1. 保留主线插件能力和定制的 Claude 上游计数、Compact V1/V2、Alpha Search、渠道搜索模拟、辅助识图、推理日志及 Claude 转 Gemini 续轮上下文。
2. WebSocket 每轮执行限流与插件处理，支持首帧恢复、切渠、并发轮间释放和逐轮结算。旧版创建的 Gemini/Vertex 任务能够继续轮询与下载。
3. 模型映射计费、超限降级、日周预算、父子渠道共享、个人提额及任务退款保留原有语义。账单归属于实际消费主体，每次消费和冲正只入账一次。
4. 保留工作流账号和令牌轮换、管理员账务摘要、同名 Key 隔离、公开日志、消息审计与 AI 复审、泄露检测。按现有角色边界接入主线限定范围的个人访问令牌。
5. 保留主线 CSV 和已有三表 Excel、历史名称筛选、缓存统计、渠道表单、七语言页面与多架构镜像构建路径。

6. 跨版本迁移覆盖 64 位额度列、视频新价格、旧面板 PAT 到期、Telegram OAuth、Redis 缓存签名和请求过滤插件。需重配的业务值来自现有业务价格与授权配置。

## Acceptance Criteria

- [ ] 使用相同输入和受控上游，在旧版与候选版分别核对出站字段、选渠、结束状态、预扣、余额、预算及最终日志。包含重试、断流、本地进度零额和多轮场景。
- [ ] 使用两名用户、同名 Key、工作流账号和父子渠道验证权限、日志隔离、预算及提额，验证旧式和限定范围 PAT 的授权调用及越权拒绝。
- [ ] 在 SQLite、MySQL、PostgreSQL 及 Redis 测试环境验证旧记录、二次启动、审计解密、历史任务和回退。核对 50 万行明细上限与完整筛选区间的报表汇总。
- [ ] 根模块、relaykit、tokenkit 构建与回归通过，前端类型检查、生产构建及关键页面通过。双侧用例、语言键和现有工作区改动有核对记录。

- [ ] 副本演练逐项记录官方兼容提醒的适用性，覆盖旧价格到插件新价格、PAT 到期前后、过滤迁移及回滚、SQLite 一致性备份、旧游乐场历史一次性清理和多节点同版切换。

## Scope

交付当前分支的本地集成候选和验证结果。独立修复分支、未提交 Worker 和其他在制工作按各自任务管理。生产发布、生产开关和对外推送留到交付评审。
