# build-bak 融合最新 main 的可行性评估

**可以立项合并。当前证据支持一个协议模块的迁移，全系统兼容仍待验证。** 建议在独立集成分支中保留 `build-bak` 的历史，合入固定的 `main` 提交。对 WebSocket、插件和分词等已重写的模块，以新版入口为基础重新接入本地行为。现有 `build-bak` 继续作为对照版本和回退点。

## 1. 对比版本和冲突规模

2026-11-27 实时查询到 `SilentFlower/new-api` 的 `origin/main` 和 `QuantumNous/new-api` 的 `main` 均指向 `81c1fd20efade39a5d5692c8018dfef4cfb30e1d`。本报告的“最新”指这个主线提交。

| 项目 | 结果 |
|---|---|
| 本地定制基线 | `build-bak@accb26db30bc5b4e8f7e81a877ebbc415f74d1d9` |
| 共同祖先 | `5c3abffe8572aa8a49f15c3916707d2019d66af4`，对应 `v1.0.0-rc.24` |
| 独有提交 | 定制侧 373，主线侧 530，均含合并与工程记录 |
| 三方试合并 | 153 个冲突路径，其中 138 个内容冲突、7 个双方新增同名文件、8 个主线删除而定制侧修改 |
| 主要目录 | `web/` 69、`relay/` 21、`controller/` 15、`relaykit/` 10、`service/` 10、`model/` 9，其余 19 |
| 自动合并仍需复核 | 以共同祖先为起点，按同路径、不识别重命名统计，两侧都改了 244 个路径。其中 92 个路径没有 Git 冲突提示。已在其中发现会阻断编译的问题。 |

Git 的 diff3 预览产生 1,847 个文本冲突块，其中 1,534 个来自七份翻译文件。反过来，10 个前端冲突文件在定制侧相对祖先的唯一改动是把 `catch (_error)` 改成 `catch`，包括上游已删除的四个旧账号安全弹窗。这些文件可优先采用新版组织方式。冲突文件逐项列于随附 CSV。

复核命令可在项目仓库执行。最后一条检测到冲突时返回状态 1。

```sh
git merge-base accb26db3 81c1fd20e
git rev-list --left-right --count accb26db3...81c1fd20e
git -c merge.conflictStyle=diff3 merge-tree --write-tree accb26db3 81c1fd20e
```

## 3. 需要额外处理的兼容问题

1. **管理接口能注册，也可能返回 403。** `router/api-router.go` 自动合入了 `POST /api/user/billing-summary` 和 `/api/token/workflow/*`。主线对新式、限定权限范围的个人访问令牌执行逐路由规则，这些直接注册的接口没有对应的主线声明。旧式 PAT 在这一步有兼容分支。定义每个定制端点可用的身份及权限，保留原 Root 限制，运行 `TestAccessTokenRouteRulesCoverEveryDashboardRoute`。自助 `/api/log/token/stat`、`/api/log/token/data` 则应按模型 Key 认证路径验收。
2. **计费范围与退款。** 单请求饱和上限、主线钱包上限、本地预算 `MaxPeriodQuota` 分别服务不同的金额边界。保留模型映射后的计费快照、任务重试重新查价、正向预算累计、客户端断流零额冲正和受信 Claude 本地回包。用相同请求比较用户余额、令牌余额、渠道用量、预算计数和消费日志。每次预扣、结算、退款均应能对应同一个请求。
3. **插件接管异步任务。** 上游删除了 Gemini 视频代理辅助文件，以及 Gemini、Vertex 两个旧任务适配器。检查旧代码增量可见，本地在这些位置加入了渠道限制、并发租约或请求取消。应在新 Google/Vertex 任务插件及宿主实际发起调用的位置验证同等行为。覆盖升级前已创建的任务、新任务、轮询和结果下载，以防历史任务丢失查询路径或跨用户占用并发。
4. **数据库、Redis 与历史数据。** `gorm.io/gorm` 从本地 `v1.25.2` 到主线 `v1.25.12`，MySQL 驱动也发生变化。本地曾因唯一索引迁移失败调整 GORM。用生产同类型副本启动候选主节点，再重启验证迁移可重入。保留主库、独立日志库、Redis 持久化配置和预算快照，核对 v2 策略、个人覆盖、父子渠道共享和缓存 Token 统计版本。采用主线可选 ClickHouse 日志库时，另验自助日志、按小时聚合和大报表查询。
5. **渠道设置、前端与语言。** 完整保存一次已有渠道，再重新读取，核对预算、视觉辅助、搜索和响应头开关。使用同一个目标分支路由生成器重建 `routeTree.gen.ts`，验证 `/log`、审计和告警页。每个语言包均有 739 个仅在定制侧、2,569 个仅在主线侧的键，父分支键并集为 8,555。逐键确认确需删除的文案，检查非英文翻译与变量占位符。
6. **构建与发布。** 主线根模块和后端 Docker 构建使用 Go 1.26.10，前端声明 Bun 1.4.4。依赖合并应保留本地 Excel 库与主线 TokenKit、插件依赖。分别构建根模块、`relaykit`、前端和实际部署架构。实际生产镜像、配置覆盖和是否启用可选日志库仍需从部署环境核实。

## 4. 已执行的验证

评估以已提交的 `build-bak` 为基线，当前工作区的 Worker、规划材料和独立修复分支另列。以下试验在临时目录执行。

| 对象 | 实验及结果 | 能回答的问题 |
|---|---|---|
| 原 `build-bak` | 控制器、模型、服务的定向回归有 79 个顶层用例通过。另有 MySQL、PostgreSQL 消息审计兼容用例各 1 个因缺少测试 DSN 跳过。Claude 转 Gemini 的 3 个专门用例在原版本通过。 | 为预算、审计、迁移、视觉辅助、WebSocket 等行为建立部分基线。数据库兼容仍需在副本上验证。 |
| 所有冲突文件整文件取 `main` 的反例 | 保留其余自动合并结果。根模块路由测试首先因缺 `github.com/xuri/excelize/v2` 无法编译。仅在实验依赖中补回 `v2.9.0` 后，编译又报告 `ChannelVisionAssistSettings` 缺失及两个 HTTP/2 PING 变量重复声明。 | 直接选上游会丢失业务依赖。编译还会被没有 Git 冲突提示的文件阻断。 |
| 同一反例的协议转换 | `relaykit` 独立构建成功，但 3 个 Claude→Gemini 回归失败，分别涉及多段系统文本、工具结果后的上下文、Read 截断提示的位置。 | 编译通过的模块依然可能改变真实请求语义。 |
| 有针对性的模块试迁 | 在另一份临时副本里，将上述续轮语义接回主线转换注册流程，再恢复 Claude Code 的 `diagnostics`、`fallbacks`、`thread` 三字段。上游已含 `safeguards`。Go 1.26.10 下 `GOWORK=off go build ./...` 成功，`relaykit` 的 `go test -count=1 ./...` 有 223 个顶层用例通过。独立 `tokenkit` 模块测试也通过。 | 这个子模块有实证可行的迁移方式。223 项是该试验副本内的用例数，整站和历史测试并集有各自的验收项。 |

试验中采用上游版本的 13 个冲突 Go 测试文件，在定制侧同路径有 48 个顶层测试名仅出现在定制侧。正式集成时应逐个映射到保留的测试或等价场景，尤其是 WebSocket、Alpha Search、查价与任务结算。

## 5. 怎样判定 build-bak 功能保住了

| 顺序 | 实施与验收 | 通过条件 |
|---|---|---|
| 1 | 固定两侧提交，以 `build-bak` 建集成分支。保留候选镜像和原镜像摘要，建立定制行为及用例对照表。 | 核心行为都有旧版本的期望值，未提交的 Worker、规划中功能与独立修复有明确范围。 |
| 2 | 先接插件、路由、DTO 和计费，再接预算并发与持久化。最后接看板、前端和翻译。 | 根模块和两个独立 Go 模块构建成功，前端类型检查与生产构建通过。权限范围覆盖测试、两侧各自新增的回归通过。 |
| 3 | 用同一组脱敏输入、同样的上游响应在旧版和候选版重放。覆盖预算到限、父子渠道、切渠重试、多轮 WS、Compact、搜索、视觉缓存、断流退款、本地进度零额回包。 | 上游实际请求内容、最终响应、渠道选择、计费模型、预扣与最终余额符合逐项预期。用户和 Key 的隔离边界一致。 |
| 4 | 用生产同类型数据库与 Redis 副本演练升级和回退。用实际类型的凭据联调 ai-fund，核对报表、历史任务与审计解密。 | 迁移重启可重入，旧数据可读，已有预算与提额保留。灰度期间新增的真实消费有对账与回退方案。 |
| 5 | 在隔离环境回放或灰度。共享 Redis 的生产节点按 rc.48/49 同版切换，记录首帧延时、长输入分词 CPU、错误率、审计队列及账务差额。 | 无跨用户数据、重复扣退或预算重置，已知行为变化有明确归因，方可扩大流量。 |

跨版本需补做视频价格重配、钱包列检查、面板 PAT 到期轮换和敏感词过滤回退演练。参见[官方兼容变更核对表](upstream-upgrade-notices.md)。

本轮结论允许开始集成。完整候选镜像、前端、真实数据库迁移及跨系统灰度属于后续验收范围。
