# 剩余 Build Feature 薄层治理：父任务设计

## 1. 设计目标

父任务负责建立六个子领域的所有权、执行顺序和最终集成门。所有子任务都只做行为不变的结构迁移，不新增公共框架，不在同一轮并发修改相同上游热点文件。

## 2. 子任务边界

| 子任务 | 独立实现目标 | 允许保留的上游接入 |
| --- | --- | --- |
| Claude 主链路 | WebSearch 模拟、渠道密钥处理、Reasoning Effort 同步 | Claude handler 条件分派；Channel CRUD 窄归一化/脱敏调用 |
| 视觉辅助 | Relay 准备、状态、错误日志与 handler 适配 | 主 Relay 单次准备/收尾调用；各 handler 单次状态读取 |
| 上游模型计费 | 计费模型解析、冻结和快照生命周期 | 价格、预扣、任务和日志层读取统一快照 |
| 公共日志与缓存统计 | 公共 Token 日志查询、脱敏、趋势、缓存 Token 聚合 | Controller 参数解析与响应；Model 旧入口薄委托 |
| Dashboard/Excel | 看板筛选、导出查询、Excel 生成和前端对话框 | 路由注册、Controller 单次导出调用、页面组件挂载 |
| 渠道设置前端 | Default/Classic build 配置独立组件与表单映射 | 主表单导入、默认值合并、组件挂载和提交结果合并 |

## 3. 热点文件所有权

- `relay/claude_handler.go`：先由 Claude 子任务处理 WebSearch 与 effort；随后视觉辅助子任务只处理剩余视觉状态接入。
- `controller/relay.go`：视觉辅助子任务处理视觉准备和错误日志；上游模型计费子任务只处理计费快照读取点。
- `model/log.go`：公共日志与缓存统计子任务先迁出公共日志/缓存统计；Dashboard 子任务随后迁出导出和看板查询。
- 两套渠道主表单只由最后的前端子任务集中修改；前五个子任务不得顺手重排主表单。

## 4. 数据流不变量

### Relay

客户端请求 → 现有解析/分发 → build 独立准备模块 → 原有 adaptor/handler → 原有计费与日志。

结构迁移不得改变请求 DTO、原始字节、模型映射、渠道、重试、错误或结算结果。

### 日志与 Dashboard

HTTP 查询参数 → Controller 边界解析 → 独立领域查询 → `LOG_DB`/缓存统计 → 原响应 DTO 或 Excel。

查询条件、分页、排序、脱敏、缓存 Token 口径和三数据库行为保持不变。

### 渠道设置

Channel `setting` JSON → 表单解析 → 独立 build 配置组件 → 合并回原 JSON。

未知字段、密钥占位状态、显式 false/0、默认值和六语言文案保持不变。

## 5. 执行波次

1. Claude 主链路：先降低 `claude_handler.go` 与 `channel.go` 冲突面。
2. 视觉辅助：在 Claude 热点稳定后处理 Relay 与 handlers。
3. 上游模型计费：收敛计费快照，避免后续日志迁移重复调整模型语义。
4. 公共日志与缓存统计：先清理 `model/log.go` 的公共日志领域。
5. Dashboard/Excel：在日志查询边界稳定后迁出看板与导出。
6. 渠道设置前端：最后统一拆分 Default/Classic 主表单，减少重复改动。

## 6. 回滚与集成

- 每个子任务可通过恢复原上游文件函数体并删除新增领域文件独立回滚。
- 子任务不得依赖尚未实施的后续子任务才能通过测试。
- 父任务最终检查六个子任务的合并结果、热点文件净差异、跨层行为和全仓回归。
