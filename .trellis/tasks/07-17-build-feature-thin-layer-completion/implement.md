# 剩余 Build Feature 薄层治理：父任务实施计划

## 1. 子任务准备

- [x] 创建父任务和六个子任务。
- [x] 固化全量范围、排除项、执行顺序和热点文件所有权。
- [ ] 每个子任务实施前完成独立 `prd.md`、`design.md`、`implement.md`、`implement.jsonl` 和 `check.jsonl`。
- [ ] 每个子任务通过 brief 审查后单独启动。

## 2. 串行实施

- [ ] 完成 Claude 主链路薄层化并归档。
- [ ] 完成视觉辅助薄层化并归档。
- [ ] 完成上游模型计费薄层化并归档。
- [ ] 完成公共日志与缓存统计薄层化并归档。
- [ ] 完成 Dashboard/Excel 薄层化并归档。
- [ ] 完成渠道设置前端薄层化并归档。

## 3. 每个子任务共同质量门

- [ ] 结构迁移前确认现有行为测试基线。
- [ ] 新增文件承担完整领域职责，原上游文件只留窄调用。
- [ ] 相关包完整回归通过。
- [ ] 关键路径定向 race 与 `go vet` 通过。
- [ ] 前端任务通过 Bun 测试、类型检查、i18n 和构建。
- [ ] `gofmt`、格式检查和 `git diff --check` 通过。
- [ ] 明确真实外部联调、三数据库实测或浏览器联调的执行状态。

## 4. 父任务最终集成检查

- [ ] 对比治理前记录，核对所有上游热点文件的净冲突面。
- [ ] 逐项复核 Relay、计费、日志、数据库和前端 round-trip。
- [ ] 运行后端相关包全量测试、定向 race、全仓测试和 vet。
- [ ] 运行 Default/Classic 可执行的完整前端质量门。
- [ ] 检查六个子任务无遗漏、无重复职责、无计划外行为修复。
- [ ] 更新 build 分支薄层治理规范和最终 Feature 状态表。

## 5. 停止条件

- 任一结构迁移无法用行为测试证明等价。
- 发现需要改变 API、计费、日志、权限、数据库或用户交互语义。
- 上游热点文件必须被大面积重写才能复用新模块。
- 出现无法归属到单一子任务的交叉修改。

触发停止条件时回到对应子任务规划，不在父任务中扩大实现范围。
