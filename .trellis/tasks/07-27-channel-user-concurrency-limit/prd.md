# 渠道单用户并发限制

## Goal

为每个渠道提供按用户维度的最大并发配置，防止单个用户通过一个或多个 API Token 同时占满同一上游渠道。渠道未配置限制时保持现有行为；渠道 `80` 在功能上线后配置为最大并发 `4`。

## Background

- 2026-07-27 上午，渠道 `80`（`cc2api_官方_anthropic`）整体峰值并发达到 `26`。
- 用户 `33`（王一铭-cop）个人峰值并发达到 `12`，是该时段最大的单一并发来源。
- 当前 relay 支持流式、非流式、Realtime/WebSocket、图片、音频、Gemini、Claude、异步任务等多种请求路径，并支持失败后重试切换渠道。
- 项目支持多实例部署；Redis 可选，未启用 Redis 时现有限流功能通常降级为进程内实现。

## Requirements

### R1. 渠道配置

- 每个渠道提供“单用户最大并发数”配置。
- `0` 或历史数据中的空值表示不限制，保持向后兼容。
- 配置只接受 `0..1000` 的整数，拒绝负数、小数和超过上限的值。
- 配置需要进入渠道缓存，编辑保存后立即生效。
- 渠道 `80` 在功能上线后配置为 `4`。

### R2. 并发维度

- 并发键必须使用 `channel_id + user_id`，同一用户的多个 API Token 共享同一限制。
- 不同用户、不同渠道的计数必须相互隔离。
- 限制只约束实际 relay 上游调用，不影响管理端渠道测试、后台管理 API 或无需选渠的任务查询。
- 对视频、Suno、Midjourney 等异步任务，只在提交、查询等实际上游 HTTP 调用期间占用名额；任务进入上游队列或后台运行后不继续占用名额。
- 视觉辅助等内部辅助 Relay 调用使用其实际辅助渠道和当前用户单独获取名额，不能绕过辅助渠道配置。

### R3. 请求生命周期

- 每次实际调用选中渠道后、访问上游前获取并发名额。
- 流式和非流式 HTTP 请求持续占用名额，直到该次上游调用结束、失败、取消或客户端断开。
- Realtime、Responses 等 WebSocket 请求按连接计数：每个已选定渠道的客户端连接占用一个名额，直到整个上游连接关闭；同一连接内的多轮请求不重复获取名额。
- 请求重试切换渠道时，必须先释放旧渠道名额，再为新渠道单独获取名额。
- 获取失败或超限时不得预扣费、结算或调用上游。
- 释放必须幂等，异常退出不得产生永久占位。

### R4. 分布式一致性与降级

- Redis 启用时使用原子操作实现跨实例共享并发计数。
- Redis 租约必须有过期保护，并在长请求存活期间续租，避免进程崩溃造成永久占位，也避免长流式请求因租约自然过期而被漏计。
- Redis 未配置时使用进程内并发限制，单实例行为必须准确；多实例无 Redis 时只保证单进程上限。
- Redis 已启用但获取并发名额失败时，采用失败关闭策略：新的受限请求返回 HTTP `503`，不得降级到单进程计数后继续放行。
- Redis 故障响应必须使用稳定的机器可读错误码，并与“达到并发上限”的 `429` 明确区分。
- 已在运行的请求如果无法续租或发现租约丢失，必须取消其上游调用或关闭 WebSocket；响应尚未提交时返回 `503`，已提交的流式响应则终止连接并记录告警。
- 续租失败或租约丢失必须按上一条终止仍在运行的请求；释放失败不得改写已经完成的成功响应，必须记录安全告警并依赖租约 TTL 完成最终回收。日志不得包含 Redis 连接凭证或用户请求内容。

### R5. 超限响应与日志

- 达到限制时立即返回 HTTP `429`，不排队、不调用上游、不扣费。
- 超限错误码固定为 `channel_user_concurrency_exceeded`；Redis 不可用或租约丢失错误码固定为 `channel_user_concurrency_unavailable`。
- 错误体必须沿用当前 OpenAI、Claude、Gemini/默认 relay 格式转换能力，并携带稳定的机器可读错误码。
- 超限属于本地容量保护，不得触发渠道自动禁用，也不得作为上游失败进行重试。
- 服务端记录请求级告警或可检索的错误日志，但不得包含 API Key、请求体或响应体。

### R6. 管理端

- `web/default` 渠道新增/编辑表单提供数值输入，放在高级设置中的渠道容量/路由类配置区域。
- 输入 `0` 表示不限；界面需要明确说明按用户统计且同一用户的多个 Token 合并计算。
- 创建和编辑 payload 均必须保留显式 `0`。
- 新增文案必须覆盖 `en`、`zh`、`fr`、`ja`、`ru`、`vi` 六种语言。

### R7. 薄层接入与上游同步

- 并发租约、Redis/内存存储、续租、释放和错误分类必须收敛在独立领域文件中，不能散落到现有 Relay 大函数。
- `controller/relay.go`、Responses WebSocket、任务、Midjourney、Claude 和视觉辅助等原有热点文件只保留获取、持有、释放、取消等窄生命周期调用，以及将标准错误交回既有响应机制的必要分派。
- 不得为了复用并发逻辑而重构、移动、改名或格式化无关上游代码；不得改变现有选渠、请求转换、计费、重试和响应顺序。
- 每个原有文件的改动必须能用一句话说明必要性；新增测试优先放入领域独立测试文件。
- 删除新领域模块并撤销各入口的薄层调用后，应能完整关闭本功能，避免形成隐式跨模块耦合。

## Acceptance Criteria

- [ ] 新建或编辑渠道可设置单用户最大并发，保存并刷新后值保持一致；从正数改回 `0` 能正确清除限制。
- [ ] 历史渠道没有新字段时默认不限，SQLite、MySQL、PostgreSQL 均能完成迁移并正常启动。
- [ ] 同一渠道、同一用户在并发达到上限后，第 `N+1` 个请求收到 `429`，且上游调用次数不增加。
- [ ] 同一用户使用不同 Token 仍共享上限；不同用户或不同渠道互不占用名额。
- [ ] 配置只接受 `0..1000` 的整数；管理 API 和前端表单均拒绝负数、小数及超过上限的值。
- [ ] 流式请求、客户端断开、上下文取消、上游错误和 panic 清理路径均不会泄漏名额。
- [ ] WebSocket 连接在整个连接生命周期只占用一个名额，多轮请求不重复计数，连接关闭后立即释放；空闲但未关闭的连接仍计入并发。
- [ ] 异步任务提交在上游 HTTP 响应结束后立即释放名额，后台任务从提交成功到最终完成的运行时间不计入并发。
- [ ] 主 relay 重试会释放旧渠道并正确处理新渠道名额，不会重复释放或跨渠道串计数。
- [ ] Redis 模式支持多实例原子限制和租约续期；Redis 未配置时进程内模式行为正确。
- [ ] Redis 已启用但运行时不可用时，新的受限请求收到 `503` 且不调用上游；不得降级为每实例各自放行。
- [ ] 长流式或 WebSocket 请求会持续续租；续租失败或租约丢失会取消上游调用/关闭连接，TTL 最终清理遗留名额。
- [ ] 超限错误不触发渠道自动禁用、不执行预扣费/结算，并按 OpenAI 与 Claude 格式返回稳定错误码。
- [ ] 渠道表单类型、校验、创建/编辑转换测试覆盖正数、`0`、负数和历史空值。
- [ ] 六种前端语言翻译完整，`bun run i18n:sync`、前端类型检查、相关 lint、Go 定向测试和 `go test ./...` 通过。
- [ ] 并发核心逻辑集中在独立 service/controller 领域文件；原有 Relay 热点只包含窄生命周期调用，没有无关重构、移动或格式化，每处旧文件修改均有明确必要性。
- [ ] 发布后渠道 `80` 的单用户最大并发配置为 `4`，并验证第 `5` 个同用户并发请求被拒绝。

## Out of Scope

- 不实现等待队列、优先级队列或请求排队超时。
- 不实现用户全局并发、模型级并发、Token 级并发或渠道总并发限制。
- 不实现异步任务的用户在途任务数限制；如需限制已提交但尚未完成的任务数量，另行设计持久化任务配额。
- 不因某渠道达到单用户上限而自动改写现有权重或自动禁用渠道。
- 不在本任务中新增并发趋势图或实时并发管理页面。
