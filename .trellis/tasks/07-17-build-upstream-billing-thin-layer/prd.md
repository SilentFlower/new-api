# 上游模型计费 Build 薄层化

## Goal

将映射后按上游模型计费的解析、冻结和读取收敛为明确的计费模型快照边界，减少价格、预扣、结算、任务和日志层的分散判断。

## Requirements

- 保持 `use_upstream_model_for_billing` 关闭、未映射、映射和重试时的计费模型选择不变。
- 保持价格表达式、分组倍率、预扣、结算、退款、违规费和 quota saturation 行为不变。
- 普通 Relay、异步任务、渠道测试和消费日志必须读取同一冻结计费模型。
- 不引入数据库或配置迁移，不改变旧 Channel setting 默认值。
- 不把计费判断复制到新的调用点；现有调用方只读取稳定快照接口。

## Acceptance Criteria

- [ ] 计费模型的解析、冻结、清理和读取职责集中且有直接测试。
- [ ] 价格、预扣、结算、任务和日志层不再各自推导计费模型。
- [ ] 跨渠道重试和配置变化不会改变已冻结的计费模型。
- [ ] 原始模型、上游模型、日志主模型和价格模型契约保持不变。
- [ ] 计费、任务、日志、退款和饱和安全回归通过。

## Out Of Scope

- 新计费模式、价格规则、表达式语法或数据库字段。
- 渠道设置前端组件拆分。
