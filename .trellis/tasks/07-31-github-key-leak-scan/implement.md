# GitHub 公共仓库 Key 泄露扫描实施计划

## 1. 后端数据与配置

1. 新增独立 operation setting 文件，注册泄露扫描开关与周期，完成 1～168 小时归一化，并只暴露外部凭据配置状态。
2. 新增扫描状态、泄露位置、通知审计三个 GORM 模型及查询/幂等更新方法。
3. 在普通迁移与 fast migration 清单中加入新模型，使用固定长度唯一键，验证 SQLite、MySQL、PostgreSQL 可迁移。
4. 为 `system_task` 增加泄露扫描任务类型，不改变现有任务状态机。

## 2. HMAC 与 GitHub 客户端

1. 实现域隔离 HMAC 指纹与稳定 16 位窗口派生；只接受长度足够的 token 和 HMAC 密钥。
2. 实现 GitHub Code Search 请求/响应 DTO，私有标记使用可区分缺失值的字段类型。
3. 实现每分钟最多 8 次 Search HTTP 请求的 context-aware 限流，分页同样计数。
4. 实现最多 1000 条结果分页、`incomplete_results`/截断检测、公开仓库过滤、有界候选下载和本地完整 Key 比对。
5. 实现鉴权、限流、超时、响应异常和候选下载失败的脱敏错误分类；禁止返回或记录请求 URL、Authorization、完整 Key 和锚点。

## 3. 扫描编排与任务接入

1. 实现未软删除 token 枚举与排序：启用优先，同组内从未扫描/最久未扫描优先。
2. 实现全量与单 token 扫描编排，任务 payload/state/result 只保存 ID、计数和脱敏状态。
3. 实现 finding 幂等写入、同路径更新、新路径识别、禁用/删除处置同步，以及“未命中不自动解除”的规则。
4. 新增周期全量与手动扫描两个 handler 并注册到现有 `RegisterScheduledSystemTasks()`；两个任务类型共享活动幂等键以全局互斥，同时保持周期全量的调度基准不受手动任务影响。
5. 在 handler 启动、每次搜索/下载和持久化前检查 `ctx` 与功能开关，确保关闭后停止后续外部请求与新增结果。

## 4. 通知与管理员处置

1. 精确命中后构造不含 Key/锚点的告警，复用现有通知机制通知 root 与 token 所属用户。
2. 实现固定安全群钉钉自定义机器人 Markdown 通知，支持可选加签、首次/新位置 `@所有人`、7 天普通提醒和单事件最多 3 次重试。
3. 持久化通知结果与脱敏错误码，确保通知失败不终止其他 token 扫描。
4. 新增 root-only 状态、finding 列表、手动扫描和一键禁用 API。
5. 一键禁用复用现有 token 状态与缓存同步路径，写入不含明文的 `token_leak.disable` 管理审计，并同步处置 finding。

## 5. 默认前端

1. 新增独立 `token-leak-scan` feature，复用 API 与类型，但把配置组件和安全告警处置组件分开。
2. 以最小注册改动接入 `系统设置 / 安全设置 / GitHub Key 泄露扫描`；该分区只放开关、周期、凭据状态、鉴权状态和覆盖说明。
3. 新增 root-only `/security-alerts/token-leaks` 文件路由与主侧边栏 `安全告警 → Key 泄露检测` 导航，承载任务状态、手动扫描、finding 表格、通知状态和禁用确认。
4. 普通用户不新增扫描页面；用户通知的处置链接指向现有 `/keys`，管理员通知指向安全告警页。
5. 手动触发期间展示已有任务与进度，避免重复提交；公开位置使用安全外链。
6. 使用 i18n key 补齐 en、zh、fr、ru、ja、vi，并运行 `bun run i18n:sync`。

## 6. 自动化测试

### 6.1 后端单元与模型测试

- HMAC 指纹稳定、域隔离、窗口边界与密钥变化。
- GitHub 分页、8 请求/分钟预算、私仓拒绝、可见性缺失、1000 条截断和不完整响应。
- 锚点命中但完整 Key 不命中的误报拒绝，以及裸 Key、`sk-` 前缀、客户端后缀场景的完整比对。
- finding 同路径幂等、新路径告警、禁用/删除停止提醒、重新启用后重开，以及连续多次重开均生成独立告警事件。
- 通知节奏、失败有限重试、消息不含 Key/锚点。
- 系统任务 payload/state/result 与错误分类不含敏感值。
- 数据模型至少执行 SQLite 测试；迁移 SQL/字段设计按项目规则检查 MySQL 与 PostgreSQL 兼容性。

### 6.2 API 与前端测试

- root 权限、参数边界、活动任务复用、凭据只返回布尔状态。
- 禁用确认后 token 状态、缓存路径、finding 与审计一致。
- 前端配置保存、任务状态、finding 列表、确认弹窗和覆盖说明。
- root 侧边栏与路由权限、配置页/处置页职责分离，以及普通用户通知跳转 `/keys`。
- `go test` 覆盖相关后端包，默认前端执行 lint/type-check/build 与相关测试。

## 7. 实现后核验

1. 执行 Trellis Check-All，重点核对 API 契约、旧数据兼容、跨层字段与日志脱敏。
2. 全仓搜索环境变量名、测试假 token 和敏感字段，确认没有真实凭据或锚点落盘。
3. 使用本地 mock GitHub/DingTalk 服务验证鉴权失败、限流、超时、分页、通知失败和取消路径。
4. 对三个数据库的迁移设计做静态核验；可用环境内至少实际跑 SQLite 自动迁移与模型测试。

## 8. 目标服务器验收与上线

以下步骤仅在代码完成、检查通过并再次取得用户部署授权后执行：

1. 创建独立、短有效期、无额外仓库权限的 fine-grained PAT；创建固定安全群钉钉机器人和随机 HMAC 密钥。
2. 通过目标服务器部署配置注入环境变量，避免命令参数、Shell 历史和日志回显具体值。
3. 发布新镜像，保持扫描开关关闭，验证服务健康、数据库迁移和凭据状态接口。
4. 插入受控假 token/公开测试内容，完成“数据库读取 → GitHub 搜索 → 候选下载 → 本地精确比对 → finding → 站内通知 → 钉钉告警”的全链路验收并清理测试数据。
5. 验证 GitHub 鉴权失败、限流和网络超时不影响主服务；验证关闭开关会停止后续扫描请求。
6. 验收通过后开启 24 小时周期任务，观察首轮任务、通知和日志脱敏结果。

## 9. 回滚验证

1. 关闭功能开关，确认不再调度新任务且当前 handler 在安全检查点退出。
2. 移除外部凭据环境变量并重启，确认主 API 转发、token 鉴权和计费不受影响。
3. 必要时回退镜像；保留新增表、finding 和通知审计，不做破坏性数据回滚。
