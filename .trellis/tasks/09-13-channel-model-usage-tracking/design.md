# Design — 渠道可选模型用量持续累计

## 1. 范围与权威配置

功能留在现有预算模块。new-api 是开关、预算统计来源和当前用量的唯一权威；ai-fund 仅转发并展示。开关放入渠道现有策略 JSON，不新增渠道表列或新的限额体系。

以下是拟新增合同，并非当前已存在的字段：

- `ChannelPeriodPolicyConfig.model_usage_tracking_enabled`：可选布尔，Go 请求侧使用指针与 omitempty 区分缺省和显式 false。旧存储缺省表示关闭；旧客户端保存时缺省保留服务端原值，不能静默关闭。
- 渠道首个开启时间、最近开启/关闭时间属于服务端维护的可选元数据，用于计算统计覆盖边界。缺省兼容旧配置，客户端不能修改历史起点。
- `ChannelBudgetRow.counter_source`：可选统计来源，缺省为现有预算计数，`continuous_model` 表示从独立模型事实聚合。只适用于 models 非空的 daily/weekly，服务端选择并保持，客户端不能任意切换。
- schema_version 保持 2，新增字段采用可选扩展；旧严格请求仍可成功，新字段的错误类型、未知值与伪造元数据被拒绝或由服务端按既有权威值归一化。

开关继续走 GET/PUT/POST preview `period-policy`，复用 revision、权限、审计、缓存及 committed=true 语义。不得另开无版本控制的设置接口。

## 2. 原始模型事实

新建 `service/channel_model_usage.go` 承载持续模型累计及存储读取，使用实际最终渠道和既有原始模型名。每个模型每日/每周各一份 Hash，字段包含 user_id、`__pool` 和统计覆盖元数据；模型名使用稳定摘要组成 key，沿用 `{channelID}` Redis hash tag。

- 开关开启：对本次正向结算模型同时写 daily/weekly。
- 开关关闭：仅在已有 `continuous_model` 预算需要该模型/周期时更新对应事实；不生成无预算模型的额外记录。
- 永未开启且没有新来源预算的渠道不进入新累计路径。
- 空模型名不创建“空模型”或把消费分摊给所有模型；保留已有兼容入口行为，相关统计缺口如实记录。
- 仅一次资金成功结算入口累计。新事实条目与旧预算条目进入同一个 Redis Lua，先预检再写；内存继续遵守既有锁顺序。整数溢出、错误 key 类型等错误不得造成部分新增或部分旧计数写入。
- 到当前日/周窗口结束后保留既有缓冲时间并过期；不预建全体用户/模型组合。任何新增内存容器必须同步清理过期周期。

## 3. 旧预算与新预算的读法

旧预算保持当前 key、值、调整和覆盖时间，不把既有模型组合数据拆成单模型，也不把原人工修改后的值复制为事实。

服务端在保存新模型日周身份时选择统计来源：渠道已开始持续累计且没有相同既有身份时，使用 `continuous_model`；相同身份已有预算时复用其来源及数据；历史身份保持旧来源。身份仍按现有 `(window, models)` 规则，个人/池子及日周时段行共享规则不变。

新来源预算读取所选模型的事实并去重聚合；没有人工调整时返回聚合值。有人工调整时按下节返回调整后的用量。旧来源预算与全部模型、occurrence 继续使用当前路径。改变模型或周期时按目标身份重新确定来源及覆盖，不把旧来源元数据硬套到另一身份。

`continuous_model` 是持久统计来源，不随开关关闭自动退回旧计数；因此关闭开关不会让现有预算用量归零。开关后续重开复用尚未过期的模型事实。已关闭区段使用渠道切换时间和模型来源覆盖信息保守标记不完整，不能声称已回填。

## 4. 手动调整与原子性

新建 `service/channel_model_usage_adjustment.go` 承载模型事实上的预算调整，使用现有预算身份、窗口和 scope/user 作为作用域。

调整保存“目标已用值 + 同一原子快照下各模型的原始值”；读取时计算目标值加快照之后的正向原始增量。Redis 在同一脚本中读取源字段并写调整快照，内存同锁；避免在 Go 先读再写造成结算增量丢失。快照整数按十进制字符串保留精度，不让 Lua/cjson 浮点数处理 int64 加总。

- A+B 的调整不修改 A、B 的事实；A 的独立预算不受影响。
- 用户调整与 `__pool` 调整分开；同一预算身份原有共享语义保留。
- 设为零后继续消费可以正确增长；管理列表和统一状态使用同一解释函数，排序/分页不能绕过调整。
- 聚合和差额在 Go 使用检查过的 int64 算术；溢出或源数据损坏返回统计不可用，禁止负值、静默 wrap 或伪造完整统计。
- 调整审计仍在权威前值读取成功后提交，保持既有 API 的绝对目标值和失败语义。

## 5. 两端 UI 与 BFF

- new-api：在现有预算策略表单的渠道级设置区域添加 Switch，使用现有 React Hook Form 草稿与预览/保存按钮；权限不足禁用。通过 i18n skill 完成七种语言。
- ai-fund：在 `PoolPeriodPolicyEditor.vue` 同一位置增加开关，随整份策略保存；号池/渠道切换、关闭弹窗及迟到响应继续遵守既有草稿/身份保护。
- 文案说明“开启后，即使未设置模型预算，也持续累计该渠道各模型的个人与池子日、周用量。会增加统计存储；关闭不影响已有预算。”
- 服务端计数来源和内部快照不进入用户操作流程；Worker、Zod 与 Vue 构造/复制配置时必须保留必要元数据，不能丢失来源或静默关闭开关。
- 统一状态与预算用量接口继续返回相同金额字段，更新 tracking_since/coverage 的计算及展示，必要的可选覆盖字段须同步 fixture。

## 6. 开销与验证

结算新事实的成本随本次模型固定为最多两个基础计数更新，合并现有单次 Redis 写脚本。请求前只读适用预算中的模型；单行上限复用现有 64 模型，使用批量读取，不按模型逐次网络往返。管理用户列表可读取选定模型的 Hash 后按用户合并，不能把 HGETALL 或全用户排序带入转发热路径。

使用隔离 Redis，对相同输入规模比较开关关闭/开启的 MEMORY USAGE、总键数、计数写命令数；Go benchmark 比较结算记录和预算读取的耗时/分配，覆盖单模型与多模型预算。报告观测结果，不能把这些子路径测量描述成生产端到端延迟承诺。

## 7. 薄接入、兼容与回滚

- 新文件集中实现原始模型事实、调整快照与测试；原 `recordChannelBudgetUsage` 只追加需要的事实条目和分派新来源预算，原调用资金结算的各业务入口不改签名或重构。
- `channel_budget_plan.go` 传递统计来源，`channel_budget_policy.go` 规范化开关和来源，`channel_budget_usage.go`/`channel_budget_override.go` 在读取/调整边界分派；`dto/channel_period_policy.go` 添加可选合同。
- 复用 common JSON、旧整数上界、缓存和审计。没有新增数据库结构迁移，策略 JSON 在 SQLite/MySQL/PostgreSQL 都要验证往返。
- 旧请求缺省新字段必须保留当前开关及已有来源；未知字段严格校验不能放宽成任意透传。
- 新旧实例混用可能把新来源预算当旧计数，因此发布必须先更新全部 new-api 实例，再开放开关及配套前端；不自动开启任何生产渠道。
- 功能关闭不等于代码回滚。若以后回退不认识新来源的旧程序，需要恢复发布前策略与对应计数，避免旧程序把新预算用量读成零；部署时按实际上线方案保留备份。
