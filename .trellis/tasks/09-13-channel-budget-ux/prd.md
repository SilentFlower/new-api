# 预算 v2 号池限制管理 UI/UX 优化（new-api + ai-fund）

## Goal

管理员在 new-api 的「渠道限额」弹窗和 ai-fund 的「号池限制」弹窗里，用同一套信息架构完成预算 v2 的配置、查看用量、提额和降级设置：一张表看懂每条预算的状态与用量，一处常驻保存栏完成预览与保存，编辑、用量、提额都从行上打开。ai-fund 号池卡片里的本人面板同步补齐状态词、已用尽强调、下次时段切换和提额标记。本任务为父任务，持有需求集、任务图与跨子任务验收；实现在两个子任务中进行。

## Background / 已确认事实

- 预算 v2 契约已由 `09-12-channel-budget-unification` 及其子任务交付并部署，本任务不改契约语义，只改界面与一个只读聚合接口。
- 代码审计与实机走查见 `research/newapi-ui-audit.md`、`research/ai-fund-ui-audit.md`、`research/newapi-visual-walkthrough.md`。核心问题：保存按钮藏在预览块底部且草稿一改即消失；时段卡片全展开、用量面板出现在页底；行状态不可见（停用/未到时段/已超限长得一样，共用计数的行画满进度条，个人行上限与剩余按不同基数显示）；个人覆盖把并发与预算提额混在一个弹窗；字段级校验不渲染、后端 message 被吞；撤销/清零无确认；new-api 每行独立请求用量，128 行即数百请求；ai-fund 预算表是「表格里的表单」必横滚，「停用预算」实际是从列表删除且无处恢复。
- 用户已确认的高保真原型：`research/channel-budget-redesign.html`（new-api）、`research/ai-fund-redesign.html`（ai-fund，含本人面板）。原型即设计规格，文字描述与原型不一致时以原型为准。
- 计数身份（`service/channel_budget_plan.go:identityKey`）：日/周窗口不含时段，带时段的日/周行与同范围同模型的无时段行共用计数；整段行按时段单独计数。界面必须如实表达这一点。
- ai-fund 号池卡片的身份/连通、健康分布条、账号卡片网格不在范围内；本人面板保留并发卡与现有两行标题格式。

## Requirements

### R1 两端共用的信息架构

- R1.1 预算表为主视图，每行：启用开关、名称与模型标签、状态徽标、范围与周期、时段（及进行中/下次开始）、上限、当前用量（进度条与剩余，按生效上限计算；个人行显示用量最高用户并标注提额）、超限动作、操作（编辑、用量、个人行另有提额）。状态徽标取值：生效中、接近上限（已用 ≥ 85%）、已超限、未到时段、已停用；停用与未到时段行整体弱化；共用计数的行以「与「X」共用计数 · 当前 Y · 此行上限 Z」替代进度条。
- R1.2 表上方摘要条：生效中 / 接近上限 / 已超限 / 已停用计数与「下次时段切换」；筛选项：全部、生效中、需关注、已停用；超限默认动作与「新增预算」放在工具栏。
- R1.3 时段改为折叠列表：每条显示名称、类型、起止、被哪些预算引用、状态（进行中 / 未开始及下次时间 / 已停用）；展开后编辑，已开始计量的时段起止只读并说明原因；停用时提示影响的预算条数。
- R1.4 保存动线：存在未保存改动时底部出现常驻保存栏（改动数、改动摘要、放弃、预览并保存）；「预览并保存」弹出逐字段 diff（预算、字段、原值、新值）与保存后各行生效结果，确认后保存；放弃、重新加载、关闭弹窗、切换号池在有脏草稿时确认；切换页签保留草稿；revision CAS 与 409 处理保持现有契约。
- R1.5 编辑表单分组：名称 / 范围与周期 / 时段 / 模型 / 上限 / 超限动作。行内校验：名称必填、整段必须绑定时段、本渠道换模型要求本行指定了模型；模型从渠道模型列表多选；超限动作三选一，降级时选目标渠道与模型；表单提供停用（不从列表移除）与复制。
- R1.6 用量与提额从行上打开：池子行显示当前窗口汇总、进度、窗口与计数起点，可调整已用金额；个人行列出用户用量并可逐个调整；提额表单固定预算行，金额须高于基础上限，可撤销。「用量」页签一次列出全部已保存行的当前用量。
- R1.7 个人覆盖拆成「预算提额」与「并发覆盖」两个独立区块，各自有列表与编辑入口。
- R1.8 反馈：撤销提额、清零/调整用量、放弃草稿弹确认；成功提示统一 toast；后端 message 透传到对应行或字段；加载、空态、错误态使用各仓共享组件。
- R1.9 术语：范围「单用户 / 池子」（ai-fund 用「个人 / 池子」）、周期「每天 / 每周 / 整段」、时段类型「指定日期 / 每周重复」；时区标注统一为服务器时区。

### R2 new-api（子任务 channel-budget-ux-newapi）

- R2.1 「用户限制状态」弹窗默认页签改为预算；页签顺序：预算、时段、用量、个人覆盖、并发。预算表、编辑 Sheet、用量 Sheet、提额 Sheet、保存栏、预览弹层按原型实现。
- R2.2 新增只读聚合接口 `GET /api/channel/:id/budgets/usage-summary`，一次返回全部预算行当前窗口用量（池子行汇总，个人行返回用量最高用户及其生效上限），权限与现有用量接口一致；预算表与用量页签只用该接口，不再逐行请求。
- R2.3 修正「本渠道换模型」写入 `selfTarget.id` 而非 `0` 的不一致（需先复核后端归一化，以后端为准）。
- R2.4 现有两份测试改为覆盖新结构；六语种 i18n 同步与源码缺键扫描通过；遵循 build 分支上游同步友好定制指南，改动限于 `web/src/features/channels` 与新增控制器/路由。

### R3 ai-fund（子任务 channel-budget-ux-aifund，实现在 `/root/project/ai-fund`）

- R3.1 worker BFF 新增聚合用量透传（`GET /pools/:poolId/budgets/usage-summary`），金额按 `quota_per_unit` 换算；fixture 由 new-api 实际响应生成。
- R3.2 `PoolLimitAdminModal` 页签改为：预算策略、时段、用量、个人覆盖、设置（渠道映射与个人并发上限）；预算表改为两行式列表，编辑、用量、提额在行下方展开；常驻保存栏与预览 diff；停用只改开关不移除行。
- R3.3 `PoolLimitPanel` 保留并发卡与两行标题；每张卡增加状态词（正常 / 即将耗尽 / 已用尽 / 进行中），已用尽卡红色边框并写明动作（拒绝或降级目标），号池额度标题右侧显示下次时段切换，提额标记放在对应卡片第二行。
- R3.4 现有 vitest 与 worker 测试改为覆盖新结构；`npm run build` 通过；规范 `.trellis/spec/backend/newapi-pool-limits.md` 同步；两仓同版本部署。

## Acceptance Criteria

- [ ] AC1 / R1 R2.1：new-api 预算表显示五种状态徽标且停用、未到时段行弱化；共用计数行显示文字说明；个人行上限与剩余按同一生效上限计算；筛选与摘要条计数正确。
- [ ] AC2 / R1.4：修改任一行后保存栏出现并计数；预览 diff 逐字段列出原值与新值，确认后 PUT body 与预览一致；有脏草稿时切页签保留、关闭/重新加载/放弃弹确认；409 后锁定并提示重新加载。
- [ ] AC3 / R2.2：打开预算页签或用量页签时用量类请求恰好 1 次，且不随行数增长；聚合接口对 128 行策略返回完整数据。
- [ ] AC4 / R1.5 R1.6 R1.8：名称为空、整段无时段、本渠道换模型但未指定模型均在表单内提示且不能完成；撤销提额、调整用量、放弃草稿均有确认；后端 400 的 message 显示在对应位置。
- [ ] AC5 / R2.4：`bun run typecheck`、`bun run lint`、渠道测试、`bun run build`、i18n 七语言同步与缺键扫描通过。
- [ ] AC6 / R3：ai-fund 管理弹窗与本人面板按原型工作；worker 全量测试、vitest、前端构建通过；fixture 来自 new-api 实际响应；本人面板并发卡与账号卡片网格不变。
- [ ] AC7 / R2.3：选择本渠道换模型后保存，读取回来的 `on_exceed.channel_id` 与后端归一化一致，摘要显示「本渠道」。

## Out of Scope

- 预算 v2 契约语义、计数身份、降级链路、迁移与旧接口。
- ai-fund 号池卡片的身份/连通、健康分布、账号卡片网格。
- 移动端专门布局（只保证不横向溢出页面）。
- 新增预算维度（monthly、通配模型等）。
