# Responses WebSocket 可恢复重试与首帧超时动态设置

## Goal

让 Responses WebSocket 的暂时性首帧超时能够通过重新建连恢复，并支持管理员在前端动态调整首帧等待时间，同时明确现有 WebSocket 的重试边界。

## Background

- 用户要求允许首帧超时恢复、梳理其他不重试场景，并将 `RESPONSES_WEBSOCKET_FIRST_FRAME_TIMEOUT_SECONDS` 接入前端动态设置；本次要求开始该任务。
- 已核实的线上请求在首帧读取阶段耗时 60.007 秒，部署版本使用默认 60 秒期限，返回 `400 invalid_request` 后关闭连接；当时尚未选渠或调用上游，也没有完整请求可供服务端重放。
- 修改前代码将首帧读取错误统一处理，无法从错误响应区分超时、报文过大和连接关闭。
- 故障证据、源码锚点、配置调用链及本次技术定稿依据见 [排查依据](research/findings.md)，其他失败分支见 [重试边界清单](research/retry-inventory.md)。

## Requirements

### R1：首帧暂时性失败恢复

- 区分首帧等待超时与不可恢复的协议、输入或连接错误，不再把暂时性超时统一表达为请求参数非法
- 超时返回语义一致的可恢复错误及关闭信号，让调用方能够重新建连并重发完整请求；不能仅删除内部 `SkipRetry` 标记
- 不在已经读取失败的原连接上循环读取，也不伪造尚未收到的 `response.create`
- 对外错误保留请求关联信息；内部诊断能够区分失败类别，不记录原始请求、对话或凭据
- 使用可识别的超时机器码与可恢复关闭信号，并以真实 WebSocket 测试证明重连恢复合同；具体组合见 `design.md`，不能承诺任意客户端一定自动重试

### R2：WebSocket 重试边界清单

- 覆盖 Responses 首帧、选渠、请求准备、上游握手与写入、流内失败、连接关闭、后续轮次及终态
- 分别标明服务端透明重试、只能由调用方重连重发，以及必须保留的不重试场景
- 说明重试次数、状态码规则、指定渠道、会话亲和、并发限制、已交付事件及 `previous_response_id` 对恢复的影响
- 普通 Responses 与 Compact V2 共用链路共同核对；Realtime 作为另一入口单独说明，不推断二者共用同一状态机
- 本次仅修改首帧读取失败的分类和恢复信号；其他分支记录现状与限制，并通过相关回归验证，不扩大自动重试范围

### R3：前端动态配置首帧等待时间

- 在现有系统设置页面增加首帧等待时间，单位秒，展示当前有效值，支持读取、编辑、保存、刷新回显及错误反馈
- 保存后无需重启，对之后新建的 Responses WebSocket 生效；已经建立的连接继续使用建立时的期限
- 设置持久化并在重启后保持；没有持久化设置时兼容现有环境变量，环境变量缺失或非法时沿用 60 秒默认值
- 优先级为有效的持久化设置高于环境变量，高于默认值；页面显示值必须与实际使用值一致
- 前后端均校验正整数与现有秒转时长的安全上限，非法值不能覆盖已生效配置；不把 `0` 解释为无限等待，也不额外降低现有有效配置上限
- 数据库保存失败须反馈失败，且不能改变运行时有效值或持久化值；历史非法站点值不能覆盖环境变量或默认值
- 复用已有设置权限、持久化和同步机制；多实例传播遵循现有同步周期，不增加配置中心
- 复用现有表单组件与布局，并同步七种语言，不重排无关设置

### R4：执行与资源边界

- 已交付事件、客户端取消或断开、权限及额度限制、连接绑定的增量上下文不能因允许重试而被绕过
- 保持既有预扣、结算、退款和并发租约生命周期，防止重复执行、重复收费或资源泄漏
- 动态更新与握手读取须并发安全，不能直接把启动期裸变量改成无保护的热更新状态

## Non-Goals

- 不修改 Codex Proxy RS、客户端、Nginx 或其他项目
- 不增加流开始后的无条件重放，不跨渠道重发缺少完整历史的增量请求
- 不修改 Realtime 协议、计费规则、历史日志或数据库结构
- 不自动提交、推送、发版、部署或重启服务；实施与本地验证在首次开工评审通过后进行

## Acceptance Criteria

- [x] AC1 / R1：真实 WebSocket 首帧超时返回 `status=408`、`error.code=responses_websocket_first_frame_timeout` 和关闭码 `1013`，保留请求关联信息；测试调用方重新建连并及时发送完整首帧后能继续正常处理
- [x] AC2 / R1、R4：非法 JSON、缺少模型仍按输入错误拒绝，报文过大保留底层关闭信号，正常关闭不再写业务错误，其他读取失败不被升级为超时或提示重试
- [x] AC3 / R2：清单逐项对应实际源码位置，明确自动重试条件、拒绝原因及未覆盖项，不把内部 `SkipRetry` 当成客户端指令
- [x] AC4 / R3：管理端可保存有效正整数，刷新回显正确，新连接采用新值，存量连接保持原期限，应用重启后仍保留设置
- [x] AC5 / R3：配置优先级可验证；非法值、非正数、小数、整数溢出及秒转时长溢出均不污染有效配置，历史非法值与数据库保存失败均有回归
- [x] AC6 / R3、R4：配置更新与并发新建连接通过相关竞态检查，既有鉴权与多实例同步边界保持
- [x] AC7 / R2、R4：已有上游失败重试、任意事件交付后不透明重试、增量续接恢复及普通/Compact 多轮路径回归通过
- [x] AC8 / R3：前端保存、失败反馈、输入校验、加载与回显可实际操作，七语言键完整，提供对应页面截图
- [x] AC9：相关测试、Go 构建与 vet、前端类型检查、涉及文件 lint/格式检查及构建通过；未执行项如实记录
