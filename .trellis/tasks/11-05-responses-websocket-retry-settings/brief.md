# Brief — Responses WebSocket 可恢复重试与首帧超时动态设置

## Goal

- 支持首帧超时后重新建连恢复，并让管理员动态调整首帧等待时间。

## Scope

- 首帧读取失败分类、超时恢复信号及安全诊断。
- 全局模型设置中的首帧等待配置、持久化和七语言文案。
- WebSocket 重试边界清单及普通 Responses、Compact 相关回归。

## Non-Goals

- 修改客户端、其他项目、Realtime、计费规则或数据库结构。
- 扩大流开始后的自动重放，或自动提交、推送、部署、重启。

## Technical Overview

- 首帧超时返回 `408`、`responses_websocket_first_frame_timeout` 和关闭码 `1013`；调用方重新建连并重发完整请求。
- 配置沿用现有 Options、管理 API 和读写锁，在每个新连接开始读取首帧时冻结期限。

## Context & Decisions

- 配置优先级为站点设置 > 环境变量 > 60 秒；接受 `1..9223372036` 整数秒，存量连接保留原期限，多实例沿用既有同步周期。
- 读取超时后原连接不能继续读取，恢复必须重连；依据 [Gorilla v1.5.0 合同](https://github.com/gorilla/websocket/blob/v1.5.0/conn.go#L1101-L1106)。
- 已交付事件、权限、额度、并发限制和增量上下文继续遵守现有重试边界；首帧失败发生在选渠和预扣之前。

## Risks

- 可恢复信号不能保证所有客户端都会自动重连。
- 无效设置、数据库保存失败和并发更新须保证有效值一致，原有账务与租约清理须避免重复。

## Acceptance

- 真实 WebSocket 验证超时封套、关闭码和重连成功，其他读取或输入错误按类别处理。
- 保存、刷新、重启重载和配置优先级正确；非法值及保存失败不污染配置，新旧连接期限符合约定。
- 普通/Compact、现有上游重试、账务与并发回归及相关竞态检查通过。
- 七语言完整、页面可实际操作并留存截图；相关测试、Go 构建与 vet、前端类型检查、lint、格式检查和构建通过，未执行项如实记录。
