# 渠道周期预算、时间规则与超限降级及 ai-fund 联动

## 目标

在 new-api 现有渠道用户限制基础上，支持个人和池子的周期额度、自定义日期／时段规则、覆盖配置，以及限额触发后转向指定渠道和模型；同步扩展 `/root/project/ai-fund` 的管理及本人状态展示。周末只是时间规则的一种使用场景，任意日期的放假也必须能够配置。

产品范围已收敛：软上限、自定义时段合计额度、个人特批优先级和首版降级范围均已确认。本文是需求与验收依据，技术方案及验证顺序分别见 `design.md`、`implement.md`。

## 用户要求

- **R1 周期与池子额度**：保留个人日周限制，增加池子日限和周限。个人及池子限制均参与新请求是否继续使用该渠道的判定。已确认使用软上限：请求开始时检查已结算用量，允许已放行的在途请求在结算后超额；不增加严格预占。
- **R2 时间控制**：个人和池子支持自定义日期／时段的限额控制与覆盖，必须能够覆盖非周末的放假日期。周末不得成为专用业务维度。“规则何时生效”与“额度如何累计和刷新”分别表达，配置包括一次性起止日期／时间与每周重复规则。已确认规则可配置时段内每日上限，并可选叠加整个自定义时段合计上限，不填写整段上限时不增加该项约束。每日额度刷新不重置尚未结束的整段累计，其他未覆盖的个人日／周限额及池子限额继续约束。
- **R3 超限降级**：默认关闭，管理员为每个来源渠道设置一个目标渠道及目标模型。个人或池子的日、周、整段金额额度耗尽均可触发；保持当前有效分组和权限边界，一次请求最多降级一次。首版支持 HTTP Chat Completions、Claude Messages、Responses，包含流式和非流式；目标可来自不同厂商，但必须兼容当前客户端接口与请求能力。WebSocket、异步任务和其他入口继续执行新增限额，首版超限返回错误。原渠道额度恢复后，后续新请求优先使用原渠道。
- **R4 双仓联动**：new-api 提供统一权威配置、状态和执行行为；ai-fund 同步管理入口和本人状态展示，使用相同规则与用量结果。
- **R5 覆盖优先级**：已确认按“个人明确覆盖项 > 指定日期规则 > 每周规则 > 默认配置”逐项解析。个人提额只覆盖明确填写的指标，未覆盖的个人日／周／整段上限以及全部池子限制继续生效；临时覆盖到期后回落当前匹配规则，永久个人提额在假期也继续生效。
- **R6 配置与统计可解释性**：同级规则对同一指标的时间重叠拒绝保存；不同指标可分别配置。界面展示规则名称、生效来源、剩余额度、下次切换及重置时间。时间规则沿用服务器时区并明确展示，服务端统一解释输入时间。新池子计数从部署后的正向结算起累计，新时段计数从规则创建后起累计，不虚构之前的历史；不完整周期显示统计起点。个人已用额度的人工调整不改变池子累计、真实账单或其他用户用量。

## 行为细则

- 池子按当前映射的 NewAPI 渠道累计该渠道所有用户的用量；同一用户的多个 API Token 共享个人额度。
- 保留整周总限额，时间规则可覆盖日限并设置整段上限。日、周和整段约束同时检查；跨周或跨月不重置尚未结束的整段额度。时间边界为包含开始、不包含结束。
- 规则结束、禁用或个人覆盖到期后自动回落下一匹配规则，已有累计不清零。正在计量的时间区间不能通过改起止时间偷偷获得新额度；额度值可调整。
- 日期规则遮盖每周规则时，较低优先级且仍处于自身计量区间的规则继续累计用量，恢复后不能获得一份空白额度。
- 降级决定在产生上游调用前完成；源渠道因超限未执行时不产生其消费，目标按重新确定的目标请求计费，日志保留原始模型、目标模型与原因。已经输出回答、已经访问上游后失败、固定渠道绑定、不可迁移的上游会话状态、目标不兼容、权限或资金不足均不能借降级绕过。
- new-api 和 ai-fund 管理端均可配置池子预算、时间规则、个人特批和降级；ai-fund 本人视图显示个人及池子状态与可解释的限制原因。无请求历史用户也能被搜索并提前配置。

## 兼容与安全约束

- 限制配置、用量和有效规则继续由 new-api 统一负责；ai-fund 的 D1 不复制用量或规则判定，只保留映射和本地审计。
- 保留 ai-fund 管理权限、字段白名单、金额换算、`expected_channel_id` 冲突校验、写后权威回读，以及旧异步响应隔离。
- 个人提额不能越过池子总预算；降级不能绕过用户余额、Token 权限或目标渠道限制。
- 现有个人提额读取失败时回落渠道默认值，因为提额只放宽限制；加入时段降额后不能直接复用该故障回落，否则可能在故障时放宽时间限制，见 `service/channel_user_limit_override.go:102`。
- 默认及规则额度的 `0` 表示不限，规则字段 `null` 表示继承；个人特批沿用有效正数和到期校验，省略某项不覆盖该项。首版不提供以零额度表达封禁的功能。
- 周期累计必须涵盖最终实际结算渠道及各正向结算入口，并维持现有防重复、溢出保护与退款口径。新增时段需明确跨时段和异步差额归属。
- NewAPI 数据模型保持 SQLite、MySQL、PostgreSQL 兼容；涉及 `relaykit` 公共类型时维持独立构建。
- NewAPI 前端新增文案覆盖七种语言；ai-fund 继续使用既有 Vue 管理工作区。

## 验收方向

- [x] **AC1 / R1**：个人或池子的日周预算任一耗尽后，新请求按开关拒绝或降级；日额度刷新不解除尚未刷新的周限制。
- [x] **AC2 / R2**：任意指定日期的放假规则，即使全部落在周一至周五也正常生效；到期后回到后续匹配规则。个人和池子均适用；额度累计与刷新按最终选定方式执行，规则切换不清空已有用量。
- [x] **AC3 / R2 / R5**：按个人明确覆盖项、指定日期、每周规则、默认配置的顺序逐项解析；假期日限 5、某人日限提额 20 时，该用户日限为 20，其他用户为 5，且该用户未覆盖的其他个人额度及池子限额仍生效。永久提额在假期继续生效；临时提额到期、撤销后回落当前时间规则，展示与执行一致。
- [x] **AC4 / R3**：关闭降级时维持明确限额错误；启用时仅按批准条件使用目标渠道和模型，并在额度恢复后自动回归。
- [x] **AC5 / R3**：目标未授权、模型不支持、目标超限或额度服务故障时不得绕过校验；无循环降级或响应开始后的中途拼接。
- [x] **AC6 / R1 / R3**：实际路由、消费日志和个人及池子用量一致；跨周期、失败、重试与重复结算符合最终确认的额度语义。
- [x] **AC7 / R4**：ai-fund 的管理员配置与 NewAPI 生效状态一致；本人页面能解释当前限制和恢复时间；切换池子或映射后不会显示或写入旧目标。
- [x] **AC8 / R1**：当前用量 80、上限 100，两个在途请求各结算 30 时允许累计到 140，后续新请求才拒绝或降级；不在检查时预占估算额度，不将软检查误报为严格不超额。

- [x] **AC10 / R2 / R6**：同级同指标重叠规则保存失败；跨周时段不清零；日期覆盖结束后下层规则仍包含遮盖期间的用量；禁用后重新启用同一规则不清零。
- [x] **AC11 / R3**：三个获准 HTTP 接口分别验证流式、非流式成功降级、禁用开关、目标不支持、最多一次、额度恢复。WebSocket、异步任务及其他入口按限额拒绝，不误触自动降级；已发生上游调用或携带不可迁移会话引用时不切换。
- [x] **AC12 / R4 / R6**：新计数在不完整周期展示统计起点；两个管理入口的版本冲突、金额换算、写后回读、权限和字段白名单保持一致。个人用量调整不重置池子或时段计数。

## 不在本轮范围

- 严格额度预占。
- 上游供应商账号原生余额同步、按 Key 的供应商独立额度管理。
- 新增协议转换器、多跳降级、流式回答中途切换模型；已有协议转换可在兼容前提下复用。
- 无用户明确要求的请求次数额度、80% 新会话降载、均匀释放预算。
- 自动同步节假日日历、独立的时段封禁、任意多个渠道合并成一个预算池、批量历史用量回填。
- 部署、线上数据库或 Redis 操作、实际渠道配置变更、提交或推送。
