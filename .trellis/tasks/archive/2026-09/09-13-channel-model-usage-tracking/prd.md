# 渠道可选模型用量持续累计

## Goal

管理员可以为指定渠道开启模型用量持续累计，之后添加模型日、周限额时能立即读取此前已记录的个人和池子用量；未开启的渠道不承担这项额外统计成本。

## Background

- 用户先询问“模型的限制能不能不加的时候用户的就积累”，随后重点确认内存和请求速度影响，最终要求：“那你实现下吧，最好不是每个渠道都这样，应该有个开关才对”。
- 当前渠道整体日、周用量始终累计；指定模型只有存在相应预算行时才计数，停用行仍累计。来源：`service/channel_budget_usage.go:150`、`service/channel_budget_plan.go:91`、`:219`。
- 当前同模型集合、同周期的个人和池子预算共享计数身份，人工调整只改变指定身份的用户字段或池子汇总。来源：`service/channel_budget_plan.go:116`、`service/channel_budget_usage.go:362`。
- 当前已发布预算 v2，原始模型名、正向结算口径、软限额以及一次降级等规则已经生效。本任务是父任务的新增子任务，不重开已交付的 v2 契约任务。

## Requirements

### R1 渠道开关

- 每个渠道独立提供“持续累计模型用量”开关，新渠道和缺少该配置的历史渠道默认关闭。
- 开启后，对该渠道实际产生正向结算的模型累计个人和池子的自然日、自然周用量，无须先创建模型预算。
- 关闭只停止未被现有预算覆盖的模型/周期的额外累计；已配置预算仍正常累计、调整和拦截。已有数据保留至正常过期，不因切换开关清零。
- 重新开启后继续使用当前周期内保留的数据；未统计的关闭区段不自动补算，统计覆盖说明不得宣称这些区段完整。
- new-api 渠道预算面板及 ai-fund 当前映射渠道的预算编辑器均可查看和设置开关；修改沿用管理员权限、版本冲突检查、预览及保存流程。

### R2 新预算使用已记录用量

- 在开启持续累计后新增模型日/周预算，可以读取当前周期内已经记录的该模型用量；单模型及多个模型合并预算都适用。
- 个人按当前用户汇总，池子按对应模型的池子汇总；多个模型去重，一笔结算不会在同一预算内重复计算。
- 例如开启后模型 A 已消费 60，再添加个人日限 100，应显示已用 60、剩余 40；设置低于已用的上限后，后续请求按既有规则拦截或降级。
- 从未开启的渠道沿用当前行为；旧预算已有用量及人工调整值保留。同计数身份的新个人/池子行继续复用其已有统计口径。

### R3 计数与调整隔离

- 原始模型累计与人工调整分离，调整 A+B 的预算不能影响 A 的独立预算、其他模型组合、池子汇总或其他用户；同身份原有共享语义保留。
- 设置已用值是绝对目标值，调整提交后发生的正向结算继续累加，不能因读写竞争丢失增量。
- 开关及统计不改变资金结算、消费日志、退款口径、原始模型归属、模型映射或降级行为。
- 缺失历史、存储故障和中断区段需明确统计边界，不以零值伪装完整历史。

### R4 开销边界

- 只为实际使用的模型创建日/周计数，沿用周期过期清理；不为所有渠道、用户或模型预建组合，不新增逐请求明细存储。
- 开启时每次结算仅增加本次模型的日、周基础累计，复用现有一次 Redis 原子批量写入，不增加同步 Redis 写往返。
- 从未开启的渠道不新增模型基础计数写入；转发和结算热路径不得为此新增逐请求数据库查询、扫描模型全集或读取历史消费日志。
- 请求前只读取适用预算涉及的模型，管理列表按所选预算聚合。验证实际 Redis 内存、Go 分配及相关路径耗时，并报告测试规模与局限，不承诺零开销。

## Acceptance Criteria

- [x] AC1 / R1：两渠道分别关闭/开启，执行相同消费后，只有开启渠道为未配置模型累计日周用量；刷新及重启后开关仍正确。
- [x] AC2 / R2：先用 60 后新增 100 限额，个人及池子读取 60/40；日、周、多个模型组合、同身份新增行分别验证。
- [x] AC3 / R1 R3：开→关→开不清空既有值；已有预算关闭开关后继续计数并拦截，未统计区段保留覆盖提示。
- [x] AC4 / R3：并发正向结算与绝对值调整不丢增量；A+B 调整不污染 A、其他组合、池子及其他人；旧预算和原人工调整值不被转换覆盖。
- [x] AC5 / R2 R3：自然日/周切换、过期清理、停用预算、模型选择变化、原始模型名为空、计数溢出及 Redis 故障均有确定性回归；Redis/内存结果一致。
- [x] AC6 / R1：两端开关读写、预览、版本冲突、权限、号池映射变更、旧客户端缺字段、非法类型和七语言均通过；新配置不能被旧字段白名单静默删除或关闭。
- [x] AC7 / R4：关闭时额外基础模型写入为 0；开启时每次结算最多新增两个基础计数 key 的更新，Redis 写往返不增加；提交真实 Redis 内存及 Go 基准对比记录。
- [x] AC8 / R3：既有预算判定、用量调整、一次降级与资金结算回归通过；fixture 覆盖完整 Go → Worker → Vue 数据流。

## Non-Goals

- 不扫描生产日志回填上线前或关闭期间的消费，不改历史账单或余额。
- 不预累计尚未配置的任意时段整段预算；整段预算保持当前语义。
- 不增加月度、滚动窗口、模型通配或严格额度预占，不新增模型统计报表。
- 本任务先完成实现、验证和交付；本轮不修改生产渠道开关或执行部署。
