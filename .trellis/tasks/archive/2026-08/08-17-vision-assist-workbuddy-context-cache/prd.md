# 视觉辅助过滤 WorkBuddy 上下文并兼容缓存

## Goal

视觉辅助处理 WorkBuddy 多模态请求时，只把真实用户问题作为识图重点，不再把 WorkBuddy 注入的身份文件、连接器状态和系统提醒发送给辅助模型；同时兼容已有视觉辅助缓存，避免部署后因缓存键变化重复识别、重复审计或重复计费。

## Background

- 2026-08-17 的线上请求通过 `/v1/chat/completions` 携带一张图片和 WorkBuddy 生成的用户消息。该消息把 `<system-reminder data-role="user-context">...</system-reminder>`、多个 `<user_query>` 块和图片本地路径放在同一个 `role=user` 文本中。
- 当前 `service/vision_assist.go` 会合并图片所属用户消息的全部文本，并把完整文本同时用于辅助请求、请求体大小规划和缓存键。
- 当前缓存键包含辅助渠道、辅助模型、识图规则、完整用户文本、多图模式和有序图片组合。直接把完整用户文本改成 `<user_query>` 内容会改变缓存键，导致已有成功缓存无法命中。
- 视觉辅助缓存只保存非空识图文本；缓存命中不会调用辅助模型，也不会生成新的视觉辅助审计或计费记录。

## Requirements

### R1. 使用已知注入块黑名单清理文本

- 视觉辅助不通过白名单提取或重建用户问题，而是从原始用户文本中删除结构完整的已知 WorkBuddy 注入块，保留其余正文。
- 首批黑名单只包含带等价 `data-role=user-context` 属性的完整 `system-reminder` 块。
- `system-reminder` 内部的身份文件、连接器状态、工作目录和其他上下文随整个块删除，不逐项匹配内部文案。
- `system-reminder` 标签名和相关属性名按 ASCII 大小写不敏感匹配，并兼容 `data-role` / `data_role`、`user-context` / `user_context` 等价写法。
- 开始标签允许常规空白、属性重排、单双引号、无引号简单属性值和无关附加属性，不依赖 User-Agent 作为唯一判断条件。
- 只删除能够可靠确定开始与结束边界的完整黑名单块。未闭合、错误嵌套或无法可靠配对的块保持原文，不得猜测性删除到消息末尾。
- 未知标签、未知注入块以及普通用户正文一律保留；后续新增黑名单项必须基于真实请求样本和明确边界。

### R2. 保留黑名单之外的全部原文

- 删除 `system-reminder` 黑名单块后，其余文本按原顺序保留，不解包、不删除也不改写 `user_query` / `user-query` 标签。
- `image_local_path` / `image-local-path` 标签、本地文件路径、图片引用标记 `@image#<序号>:` 和普通文件名全部保留，并实际发送给视觉辅助模型。
- 多个剩余文本片段在黑名单删除边界处使用稳定换行分隔，避免前后文本粘连。
- 只清理由黑名单块删除产生的首尾和相邻边界空白，不全局压缩或重写 Markdown、换行、Windows 路径、比较符号和未知标签。
- 清理后没有有效正文时，视觉辅助使用空问题并退化到通用识图规则，不重新注入被删除的上下文。
- 未删除任何黑名单块时保持原始文本不变。
- 过滤只影响派生的视觉辅助请求；主请求中的原始消息、工具上下文和后续写回结构保持不变。

### R3. 缓存键使用过滤后的稳定文本

- 新缓存键继续包含既有辅助渠道、辅助模型、识图规则、多图模式和有序图片组合，但用户文本部分改用实际发送给辅助模型的过滤后文本。
- 同一图片、同一保留正文、相同识图配置必须命中新缓存，即使 WorkBuddy 黑名单块中的工作目录、身份文件或连接器状态发生变化。
- 本地路径属于保留正文；`image_local_path` 标签或路径值变化必须形成不同缓存键，不要求跨本地路径复用。
- 同一图片但保留正文不同必须形成不同缓存条目。
- 请求内重复图片和等价批次继续使用新缓存键去重，不得增加辅助调用次数。

### R4. 兼容已有缓存

- 保留原始用户文本用于构造旧缓存键；不修改 `vision_assist:v1` 命名空间和缓存值结构。
- 查询顺序为新缓存键优先，未命中时查询旧缓存键。
- 旧缓存键命中时直接复用识图结果，并按当前渠道 TTL 回填新缓存键；回填失败只记录现有风格的告警，不得重新调用辅助模型。
- 旧键命中与新键命中都按普通缓存命中统计，不生成新的视觉辅助审计、预扣费或消费记录。
- 新上游结果只写新缓存键，避免 WorkBuddy 动态上下文形成长期双份高基数缓存。
- 失败或空识图结果继续不写缓存。

### R5. 可观测性与隐私边界

- 不新增用户原文、WorkBuddy 上下文、图片路径、图片内容或缓存键明文日志。
- 现有 `vision_assist_cache_hits`、批次数、图片数、重试和失败统计语义保持不变。
- 消息审计仍只记录真实发生的辅助调用；新键或旧键命中均不得伪造辅助审计记录。

### R6. 回归兼容

- OpenAI Chat、Claude Messages 和 OpenAI Responses 的用户问题与图片绑定规则保持不变。
- 历史图片的纯文本追问不得改变首次图片问题或触发重复识别。
- 多图分批、请求体 8 MiB 上限、图片写回、重试、失败策略和计费行为保持不变。

## Acceptance Criteria

- [ ] AC1：使用线上结构的 WorkBuddy 测试夹具时，辅助请求不包含 `system-reminder`、身份文件或连接器状态，但完整保留 `user_query`、`image_local_path` 和本地路径原文。
- [ ] AC2：多个用户查询块、图片引用标记和路径块按原顺序保留；删除系统提醒后没有剩余正文时使用通用识图规则。
- [ ] AC3：系统提醒标签的大小写、空白、属性顺序、单双引号、附加属性和属性下划线/连字符写法变化时，得到相同的过滤后文本。
- [ ] AC4：普通用户文本、用户查询标签、图片路径标签、未知标签和未知注入块均按原文保留；畸形系统提醒块不得发生越界删除。
- [ ] AC5：预置旧缓存键后执行等价 WorkBuddy 请求，辅助 caller 调用次数为 0，结果被复用且新缓存键完成回填。
- [ ] AC6：两个请求的图片与保留正文相同，仅系统提醒内容或受支持的标记写法不同时，第二次命中新缓存且不调用辅助 caller。
- [ ] AC7：图片相同但过滤后保留正文、本地路径、图片内容、顺序、识图规则、辅助渠道或模型变化时，不得错误复用缓存。
- [ ] AC8：缓存命中不产生视觉辅助独立审计、预扣费或消费；回填失败不改变已命中的返回结果。
- [ ] AC9：现有历史图片追问、多图分批、请求内去重和缓存复用回归测试继续通过。
- [ ] AC10：通过视觉辅助聚焦测试、竞态测试、Relay 回归构建、全量 Go 测试、`go vet` 和 `git diff --check`。

## Out of Scope

- 为图片抠图、图片修改或图片生成新增模型路由或工具调用。
- 修改 WorkBuddy 客户端的消息组装方式。
- 保存或展示 Gemini 原始响应正文，或增强空响应的 `promptFeedback` / `finishReason` 诊断。
- 修改渠道配置表单、数据库结构、公开 API 或 Relay DTO。
