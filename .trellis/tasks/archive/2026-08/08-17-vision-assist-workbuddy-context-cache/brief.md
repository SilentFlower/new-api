# Brief — 视觉辅助过滤 WorkBuddy 上下文并兼容缓存

## Goal

- 视觉辅助删除 WorkBuddy 已知注入块、保留其余用户正文，并在缓存键切换时复用已有成功缓存，避免重复识别、审计和计费。

## Scope

- 在 Service 层用小型线性扫描器删除 WorkBuddy 系统提醒块，兼容大小写、空白、属性顺序、引号及相关属性的 `_` / `-` 写法。
- 黑名单首批只包含 `data-role=user-context` 系统提醒块；身份文件、连接器状态和工作目录随系统提醒整体删除。
- 用户查询标签、图片本地路径标签、路径值、图片引用标记、未知标签和其他剩余原文全部保留。
- 让辅助请求、请求体大小规划和新缓存键使用过滤后文本。
- 使用过滤后文本构造 primary key，并在未命中时兼容查询原始文本对应的 legacy key。
- Legacy 命中后直接复用并回填 primary key；请求内去重和后续成功写入统一使用 primary key。
- 增加 WorkBuddy 黑名单过滤、旧缓存迁移、新缓存复用和现有视觉辅助行为的 Go 回归测试。

## Non-Goals

- 不新增图片抠图、图片修改或图片生成能力与路由。
- 不修改 WorkBuddy 客户端消息组装。
- 不保存 Gemini 原始响应正文，也不扩展空响应诊断。
- 不修改数据库、渠道 DTO、公开 API 或前端配置。

## Key Decisions

- 不通过白名单提取或重建用户问题；primary cache key 直接使用“原文减去完整系统提醒块”的过滤后文本。
- 系统提醒标签与相关属性按 ASCII 大小写不敏感匹配，兼容附加属性、属性重排、单双引号以及相关属性的 `_` / `-` 写法。
- 每个黑名单块独立严格配对；边界异常时保留对应原文，不猜测性删除到消息末尾。
- 未删除任何黑名单块时保持原始文本不变；清理后没有正文时使用空问题和通用识图规则。
- 过滤只作用于派生视觉辅助数据，主请求和后续写回继续保留完整原始内容。
- 新缓存键使用实际发送的过滤后文本；旧缓存键只用于兼容读取，不升级 `vision_assist:v1` 命名空间或缓存值结构。
- 查询顺序为 primary -> legacy -> caller；legacy 命中后按当前 TTL 回填 primary，且不进入辅助调用、审计或计费。
- 新结果只写 primary，避免 WorkBuddy 动态上下文造成长期双写和高基数缓存膨胀。

## Key Context

- 核心实现位于 `service/vision_assist.go`；现有用户消息绑定测试位于 `service/vision_assist_user_message_test.go`，多图缓存测试位于 `service/vision_assist_batching_test.go`。
- 当前缓存键包含辅助渠道、模型、识图规则、用户文本、多图模式和有序图片源；请求 ID、会话 ID和消息索引不得进入缓存键。
- 历史图片的纯文本追问必须复用首次识图缓存，不得因本次改动重新识别。
- 缓存命中不能产生视觉辅助独立审计；只有真实 caller 尝试才进入审计、预扣费和结算链路。
- `HybridCache` 不提供剩余 TTL，legacy 回填使用当前渠道配置的规范化 TTL。

## Risks / Deferred

- WorkBuddy 使用全新注入标签时，未知块会被保留并进入辅助请求和缓存键；后续基于真实请求将边界明确的新块加入黑名单。
- 本地路径明确保留在辅助请求和 cache key 中；路径变化会造成缓存未命中，并可能向辅助模型暴露客户端路径，这是已接受的行为。
- Legacy 成功缓存由旧的完整上下文生成，回填可能延长其生命周期，但可避免重复识别，且缓存身份仍完整绑定图片、问题、规则、渠道和模型。
- 当前线上是单 new-api 实例；多实例混跑新旧版本时不做永久 legacy 双写，发布窗口需要尽快完成版本收敛。
- 图片编辑意图路由与 Gemini 空响应诊断留待独立任务处理。

## Acceptance

- WorkBuddy 线上结构的辅助请求不包含系统提醒、身份文件或连接器状态，但保留用户查询标签、本地图片路径和其他剩余原文。
- 系统提醒标签的大小写、空白、属性顺序、引号、附加属性和相关属性 `_` / `-` 写法变化时得到相同过滤后文本和缓存键。
- 普通文本、用户查询标签、图片路径标签、未知标签和未知块保持原文；畸形系统提醒块不发生越界删除。
- 预置 legacy key 后 caller 不执行，识图结果复用并完成 primary 回填。
- 系统提醒内容或写法变化但图片和保留正文相同时命中新缓存；本地路径、其他保留正文或图片/识图配置变化时不错误复用。
- 新旧缓存命中均不产生辅助审计、预扣费或消费，现有缓存命中统计保持一致。
- 视觉辅助聚焦测试、竞态测试、Relay 回归、relaykit 独立构建、全量 Go 测试、`go vet` 和 `git diff --check` 全部通过。
