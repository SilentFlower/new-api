# 修复 Claude 消息审计会话归并

## Goal

修复 Claude Messages 入站请求因瞬态元数据或等价载荷表示变化而被错误拆分为多个消息审计会话的问题，同时保持每次请求的加密审计正文、Relay 行为和其他协议会话语义不变。

## Background

- 当前审计在请求校验后、渠道选择和上游覆盖前捕获已验证入站 DTO；该时序保证渠道选择、重试、协议转换和计费失败不会改变审计覆盖范围。
- 生产服务器过去 24 小时内，Claude 审计 5740 条中有 5071 条被判定为 `new`，明显高于 OpenAI Responses 的新会话比例。
- 生产样本的连续 Claude 请求实际保留了完整历史并仅追加消息，但以下差异会改变当前基于完整规范化 JSON 的滚动 HMAC：
  - `system` 中 `x-anthropic-billing-header` 的瞬态 `cch` 值变化；
  - `cache_control` 在历史内容块之间移动或消失；
  - 相同文本在字符串和单个 `text` block 数组之间切换。
- 异常样本使用的渠道没有参数覆盖或 system prompt 覆盖，只有通配请求头透传；上述差异已存在于审计捕获的入站请求体中，不是渠道覆盖写入。
- 现有 Claude 测试覆盖协议支持、工具计数和详情语义角色，但没有使用真实 Claude Code 连续请求形态验证 exact/prefix 会话归并。

## Requirements

- R1：继续在请求校验后捕获原始已验证入站 DTO，不把消息审计移动到渠道选择、请求体覆盖、请求头覆盖或上游发送之后。
- R2：加密保存、详情解密、消息块去重、消息数量和工具调用数量必须继续基于现有安全过滤后的入站内容；修复不得重写或丢弃审计正文中的 `system`、`cache_control` 或原始内容表示。
- R3：Claude 会话指纹必须使用独立的语义规范化副本，至少消除以下非会话身份差异：
  - `cache_control` 字段；
  - `x-anthropic-billing-header` 中变化的 `cch` 参数，同时保留其他稳定 system 指令的区分能力；
  - 纯文本字符串与语义等价的单个 `{type: "text", text: ...}` 内容块表示。
- R4：Claude 的用户、助手、工具调用、工具结果以及稳定 system 内容发生真实变化时，仍必须改变会话指纹；不得退化为按用户、时间、模型或首条文本模糊归并。
- R5：OpenAI Chat、OpenAI Responses、Gemini 和图片协议的现有规范化、会话指纹、压缩识别和独立会话行为不得改变。
- R6：修复不得改变 Relay 请求体、Header Override、参数覆盖、模型映射、渠道重试、计费、错误返回或审计 fail-open 行为。
- R7：新增生产形态回归测试，覆盖动态 `cch`、移动的 `cache_control`、字符串/单文本块等价表示、真实内容变化和非 Claude 协议不受影响。
- R8：实现应保持 build 分支上游同步友好；Claude 指纹规范化逻辑集中在独立 service 文件，现有消息审计主流程只保留必要的薄接入。
- R9：本次不回填或重写上线前已拆分的历史审计记录；修复只对新捕获请求生效，不执行生产数据修复操作。

## Acceptance Criteria

- [ ] 连续 Claude 请求仅追加新消息时，即使 `cch` 改变、旧消息的 `cache_control` 被移动或相同文本表示在字符串/单文本块之间切换，仍继承同一 `audit_session_id` 并标记为 `prefix`。
- [ ] 规范化后完全相同的 Claude 请求能够标记为 `exact`。
- [ ] Claude 的稳定 system 指令、可见消息文本、工具调用参数或工具结果发生真实变化时，不会被错误视为相同前缀。
- [ ] 单条审计详情仍返回该次请求实际捕获的安全过滤后内容，不返回指纹规范化后的替代表示。
- [ ] 现有 exact/prefix/compressed/new 会话推断测试和其他协议消息审计测试全部通过。
- [ ] 新增测试使用 `testify/require` 与 `testify/assert`，并直接保护会话归并行为而非私有常量或实现细节。
- [ ] 不新增数据库字段、数据库方言分支、前端改动或渠道覆盖时序改动。
- [ ] 不提供历史回填脚本，不解密并重算既有审计记录，不重写既有会话父子关系或审核关联。

## Out Of Scope

- 修改客户端或要求客户端提供 session/thread/conversation 标识。
- 依据最终上游请求体、渠道、模型名或时间窗口进行会话归并。
- 修改消息审计 UI、AI 重审协议或正常 Relay 请求内容。
- 生产部署与数据库数据修复操作。
