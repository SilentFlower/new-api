# Brief — 优化视觉辅助模型选择与消息审计

## Goal

- 将视觉辅助配置改为可搜索、可联动的选择体验，把每次实际辅助调用作为独立消息审计记录，并为 `combined` 多图模式增加可配置、可缓存复用的有界自动分批。

## Scope

- 新增只返回启用渠道 `id`、`name`、`models` 的精简管理 API，不暴露渠道密钥或其他敏感配置。
- 将视觉辅助渠道改为可搜索选择器，模型随渠道联动，同时保留自定义模型输入能力。
- 保留历史失效渠道和模型的当前值；切换渠道时清空旧模型，并覆盖加载、空数据和失败状态。
- 为消息审计增加请求类型与关联请求 ID 元数据，历史空类型按普通客户端请求处理。
- 在最终辅助协议 DTO 准备完成后启动独立 capture，并统一 finalize 后续 token、计费、并发、上游和响应处理结果。
- 每个视觉辅助重试生成独立记录；缓存命中不生成记录。
- 消息审计列表标识视觉辅助记录，详情支持视觉辅助记录与主请求双向导航。
- 为 `combined` 模式增加渠道级 `combined_max_images`，默认 `5`、范围 `1-64`；同一消息超量图片按原始顺序自动分批。
- 后端使用固定 `8 MiB` 请求体安全上限提前切割过大的内联图片批次，单张超限图片独立成批并沿用现有失败策略。
- 自动分批保持确定性；缓存 TTL 内的新会话重复提交相同问题和有序图片时逐批命中 HybridCache，不重复调用、审计或计费。
- 日志记录生效上限、批次数、各批图片数、切割状态和稳定切割原因。
- 补齐后端、前端、四种辅助端点、会话隔离、历史兼容和 i18n 回归验证。

## Non-Goals

- 不自动探测上游尚未登记的完整模型列表。
- 不修改视觉辅助触发、提示词、`separate` 模式、重试、计费、并发或失败策略。
- 不把联合识别结果拆成可跨任意组合复用的单图缓存；仅复用实际输入完全等价的有序批次。
- 不开放请求体字节上限的前端配置；仅开放单批图片数量上限。
- 不重构原始图片转发策略，不新增持久图片路径、对象存储句柄或图片编辑 Agent 协议。
- 不保存视觉辅助模型响应正文或原始图片正文。
- 不把视觉辅助记录并入主请求推断会话或主会话 AI 重审材料。
- 不新增视觉辅助类型的消息审计列表筛选器。

## Key Decisions

- 采用“独立审计记录 + 关联主请求”，不把辅助请求正文嵌入主请求详情。
- 一个真实辅助调用尝试对应一条记录，内部重试分别记录。
- 新增独立的 `request_kind` 与 `related_request_id` 元数据，不复用承担会话链语义的 `parent_request_id`。
- 视觉辅助 capture 使用 standalone 会话语义，跳过普通会话指纹归并。
- 关联字段使用普通索引且不建立外键，避免异步入队、保留清理和三数据库兼容性受到写入顺序约束。
- 模型控件允许自定义值，渠道控件不允许自定义 ID。
- `combined` 表示同一消息内有界联合分析，默认每批 `5` 张；图片数或固定 `8 MiB` 请求体安全上限触发时稳定拆批。
- `combined_max_images` 写入 `relaykit/dto.ChannelVisionAssistSettings`，并保持 `relaykit` 可在 `GOWORK=off` 下独立构建。
- 缓存键不包含请求 ID、会话 ID、消息索引、批次序号或 worker 顺序，只包含影响识别结果的渠道、模型、提示词、用户问题和有序图片内容。
- 上限变化导致图片组合变化时不复用旧联合结果；实际组合未变化时允许继续命中缓存。

## Key Context

- 当前手填字段位于 `web/src/features/channels/components/drawers/sections/build-channel-settings.tsx`。
- 主请求唯一审计入口位于 `controller/relay.go`；视觉辅助调用位于 `relay/vision_assist.go`，当前绕过该入口。
- 最终辅助 DTO 在 `prepareVisionAssistRequest` 成功后可用，支持 OpenAI Chat、OpenAI Responses、Claude Messages 和 Gemini Native。
- 消息审计现有 `ParentRequestID` 用于推断会话链，不能用于视觉辅助关联。
- 新选择器和审计生命周期主体放入独立文件，原有上游文件仅保留路由、字段、调用和渲染接入。
- 前端使用 React Query、React Hook Form、现有 Combobox 与 Base UI 受控值契约；新增文案通过 i18n 工作流同步七语言。
- 现有视觉辅助缓存为 Redis 优先、进程内 LRU 兜底的 HybridCache，默认 TTL 为 `86400` 秒；缓存命中不会进入辅助 caller。

## Risks / Deferred

- 真实重试会增加审计记录数量，但数量受现有视觉辅助重试上限约束。
- 主请求和辅助请求均异步非阻塞入队，极端队列压力下可能只保存一侧；无外键设计保证单侧缺失不阻塞另一侧。
- capture 后任一错误分支遗漏 finalize 会留下 pending，必须通过统一 defer 和失败回归保护。
- 历史值合成选项遗漏会破坏受控 Combobox 显示、焦点或键盘行为，需要组件交互测试。
- 关联主请求被保留策略删除后，辅助记录只保留不可跳转的历史 ID。
- 远程图片 URL 在调用前无法获知真实媒体大小，固定字节安全上限只能精确约束内联图片；所有图片来源仍受数量上限约束。
- 联合结果依赖同批图片组合和顺序，不能为了提高命中率而错误复用不同分批边界的缓存。
- `strip_image=true` 可能阻断需要原始像素的图片操作 Agent；`strip_image=false` 可能造成目标模型重复识图，或被不支持视觉的上游拒绝。当前没有可供 Agent 跨请求访问的稳定图片路径，该问题单独延后设计。

## Acceptance

- 管理员可按渠道名称或 ID 选择辅助渠道，并搜索、选择或自定义辅助模型。
- 历史失效渠道和模型不丢值，切换渠道只清空旧辅助模型。
- 每个非缓存命中的视觉辅助调用尝试产生带明确类型和主请求关联的独立审计记录。
- 视觉辅助记录与主请求可双向打开，且辅助记录不参与主请求会话归并或 AI 重审材料。
- 审计正文对应最终辅助协议 DTO，不包含原始图片正文；成功和失败路径均正确 finalize。
- 审计不可用不影响视觉辅助调用；缓存命中不生成记录。
- `combined_max_images` 可按渠道动态配置，旧配置默认 `5`，超量图片按顺序切割且不跨用户消息。
- 两个独立请求在 TTL 内提交相同问题和相同有序图片时，第二次全部命中分批缓存，辅助 caller 调用次数为 `0`。
- 分批上限变化导致图片组合变化时不会误命中旧联合结果；`separate` 模式保持不变。
- 自动分批保持现有 `strip_image` 语义：关闭移除时原始媒体块内容与顺序不变，开启移除时维持现有移除行为。
- 日志可核查实际批次数、批次大小、切割状态、切割原因和生效图片上限。
- 四种端点模式、历史兼容、三数据库迁移、前端交互和七语言门禁均通过验证。
