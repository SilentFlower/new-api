# Brief — GitHub 公共仓库 Key 泄露扫描

## Goal

- 为目标 new-api 实例建立用户 API Key 的 GitHub 公共仓库泄露检测、脱敏告警与可审计处置能力，完整 Key 始终只留在服务器内存中。

## Scope

- 扫描 `model.Token.Key` 对应的全部未软删除用户令牌；启用令牌优先，禁用、耗尽和过期令牌低优先级补扫。
- 使用 HMAC-SHA256 为每个 Key 生成稳定不可逆指纹，并稳定派生一个连续 16 位搜索锚点；同一密钥下不因重复扫描暴露更多片段。
- 通过独立、无额外仓库权限的 fine-grained PAT 查询 GitHub 全站公开代码；每分钟最多 8 次 Code Search HTTP 请求，分页请求计入预算。
- 拒绝私有或可见性未知结果，下载公开候选后在服务器内存中使用完整 Key 精确比对；锚点命中本身不算泄露。
- 新增扫描状态、泄露位置和通知审计持久化，保证同一 token/仓库/路径幂等更新；未命中不能自动解除既有泄露记录。
- 接入现有 `system_task`：主节点调度、任务互斥、租约和进度复用；默认 24 小时，可配置 1～168 小时，首次启用立即执行，并支持 root 手动全量或单 token 扫描。
- 精确命中后通知 root 管理员和 token 所属用户，同时通过固定安全群钉钉自定义机器人发送 Markdown 告警；首次、新增位置或处置后再次重开分别使用独立幂等事件，首次或新增位置 `@所有人`，未处置且仍启用时每 7 天普通提醒。
- 提供 root-only 状态、finding 列表、手动扫描和二次确认一键禁用 API；禁用操作写管理审计，不自动禁用。
- 在 `系统设置 → 安全设置 → GitHub Key 泄露扫描` 中只展示开关、周期、凭据配置状态、鉴权状态和覆盖盲区。
- 在 root 主侧边栏新增 `安全告警 → Key 泄露检测` 独立处置页，展示任务进度、手动扫描、泄露列表、通知状态和禁用操作。
- 普通用户不新增扫描页面；用户通知引导其进入现有 `/keys` 页面处置自己的 token，管理员通知进入安全告警页。
- GitHub PAT、HMAC 密钥、钉钉 Webhook token/可选签名 secret 只通过环境变量注入，管理 API 仅返回是否配置。

## Non-Goals

- 不扫描 `model.Channel.Key` 或其他上游供应商凭据。
- 不读取、报告或搜索私有仓库，不限定为授权账号自己的仓库。
- 不调用发现的 Key 验证有效性，不自动禁用、删除或轮换生产 Key。
- 不实现 GitHub Secret Scanning Partner 集成，也不承诺零漏报或全历史覆盖。
- 不覆盖非默认分支、历史提交、已删除/未索引内容，以及被拆分、转义或编码的令牌。
- 首版不实现钉钉用户账号映射、应用机器人单聊或个人定向通知。
- 不为普通用户新增泄露 finding 查询页面，也不向普通用户暴露其他用户、仓库命中汇总或管理员处置数据。
- 本轮规划确认不等于生产部署授权；目标服务器发布、注入凭据和启用任务需在实现及检查通过后再次确认。

## Key Context

- 现有调度入口为 `service/system_task.go`、`model/system_task.go` 和 `controller/system_task_handlers.go`；新增任务必须复用现有主节点、按类型互斥和租约语义。
- 用户令牌定义在 `model/token.go`，`Token.Key` 最长 128 字符且使用 GORM 软删除；本地完整子串匹配可同时覆盖裸 Key、`sk-` 前缀和客户端后缀形式。
- 站内通知复用 `service/user_notify.go` 的 `NotifyRootUser`/`NotifyUser`，管理操作复用 `controller/audit.go` 的审计路径。
- 新表必须加入普通迁移和 fast migration 清单，并同时兼容 SQLite、MySQL 5.7.8+、PostgreSQL 9.6+；优先使用 GORM，固定长度 finding key 承担跨数据库唯一约束。
- GitHub 客户端使用 `net/http` 和项目 `common` JSON 包装函数；不得依赖 `gh` 登录态或新增宽权限 OAuth 授权。
- 搜索 URL包含 16 位锚点，钉钉 URL包含机器人 token；不得直接记录请求 URL、请求头、原始传输错误或响应正文，错误统一映射为脱敏代码。
- 完整 Key、锚点、PAT、Webhook 凭据不得进入数据库、日志、任务 payload/state/result、管理 API、测试夹具或仓库文件。
- 功能默认关闭；handler 在启动及每次外部请求/持久化前检查开关和 `context`，关闭后停止后续请求与新增写入。
- 默认前端配置路由为 `/system-settings/security/token-leak-scan`，root 日常处置路由为 `/security-alerts/token-leaks`；二者共享 feature API/类型但保持职责分离。
- 首轮生产启用前必须用受控假 token 完成数据库、GitHub、精确比对、持久化、站内通知与钉钉的全链路验收，并验证鉴权失败、限流、超时、互斥、脱敏和回滚。

## Acceptance

- 可枚举并按优先级扫描全部未软删除用户令牌，稳定生成指纹与 16 位锚点；GitHub 请求和所有持久化/日志均不含完整 Key。
- Code Search 严格执行每分钟最多 8 次请求、分页上限、公开仓库过滤、超时、有限重试、可取消和不完整结果标记。
- 只有公开候选中的完整 Key 本地精确命中才生成 finding；相近字符串被拒绝，同一路径重复扫描幂等，新位置立即告警。
- 周期任务默认 24 小时、可配置 1～168 小时，首次启用立即执行，多节点只由主节点执行，关闭后不再调度或继续外部扫描。
- 精确命中同时通知 root 与所属用户；钉钉首次/新位置 `@所有人`、同一开放位置 7 天至多普通提醒一次，禁用或删除后停止提醒并保留审计。
- 一键禁用必须二次确认，更新 token 状态及缓存路径，处置 finding，并记录不含明文的 `token_leak.disable` 管理审计。
- 系统设置页只负责配置和凭据状态；root 侧边栏安全告警页负责任务与 finding 处置，两个路由权限正确且新增文案覆盖 en、zh、fr、ru、ja、vi。
- 普通用户通知只包含其自身 token 的脱敏标识并跳转现有 `/keys`，不能访问 root-only finding 数据。
- 自动化测试覆盖 HMAC、分页/限流、私仓拒绝、误报拒绝、幂等、通知节奏、敏感信息不落盘、root 权限与禁用审计；相关 Go 测试及默认前端 lint/type-check/build 通过。
- 目标服务器受控假 token 全链路、失败场景和回滚验收通过后才允许开启生产周期任务；关闭/回退不影响原有 API 转发、鉴权和计费。
