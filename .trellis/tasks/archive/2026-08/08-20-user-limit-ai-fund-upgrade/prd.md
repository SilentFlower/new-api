# 用户限额与 ai-fund 升级

## Goal

升级渠道级单用户限制：在现有并发上限和每日额度软上限基础上增加每周额度软上限，并允许管理员为指定用户设置高于渠道默认值的个人覆盖上限，可选自动过期。同步升级 ai-fund 号池页面，使普通用户能查看自己的日/周额度与并发状态，管理员能通过 Cloudflare Worker 安全管理渠道默认值、个人覆盖值和当前周期使用量。

## Background

- NewAPI 渠道模型当前只有 `user_concurrency_limit` 与 `user_daily_quota_limit`，定义位于 `model/channel.go:54-55`。
- 每日额度按 `channel_id + user_id + 服务端自然日` 统计，是请求前检查已结算累计的软上限；Redis 不可用时按现有失败关闭语义处理，未配置 Redis 时使用单实例内存状态，见 `.trellis/spec/backend/channel-user-daily-quota.md:9-12`。
- 当前个人额度操作修改的是“当日已使用额度”，不是个人上限；它不能表达可审计、可自动过期的临时提额，见 `.trellis/spec/backend/channel-user-daily-quota.md:182-184`。
- 订阅周期已有“下周一 00:00”计算约定，见 `model/subscription.go:358-367`；新增周限应复用同一自然周边界和服务端时区语义。
- ai-fund 当前任务 `/root/project/ai-fund/.trellis/tasks/08-20-pool-user-limits` 已通过 Cloudflare Worker 代理 NewAPI 的每日额度和并发接口，并在 `/pools` 页面提供普通用户视图与管理员管理入口。
- ai-fund 的 D1 当前用于号池渠道映射和本地审计；实际限制必须由 NewAPI 持有和执行，不能让 Relay 热路径依赖 CF Worker 或 D1。

## Requirements

### NewAPI 渠道默认限制

- 渠道新增 `user_weekly_quota_limit`，取值 `0..common.MaxQuota`；`nil`、历史 `NULL`、显式 `0` 和异常负值读取时均表示不限。
- 周限与每日额度保持同样的软上限语义：请求前只检查当前周期已结算累计，不预占本次估算额度，并发请求允许造成小幅超额。
- 日限与周限同时启用时必须同时满足；任一已达到上限都阻止新请求，且不预扣、不访问上游、不换渠重试、不自动禁用渠道。
- 周期固定为服务端时区的自然周，周一 `00:00` 开始；使用新周期 key 自动刷新，不依赖定时清空。
- 所有正向渠道额度必须同时记录到日、周状态；退款、负向差额和管理员退款不回退周期累计，保持与现有每日额度一致。
- 管理员可分页查看当前自然周有使用记录的用户，并可把指定用户本周已使用额度设置为合法目标值，包括 `0`。

### 用户个人覆盖上限

- 管理员可按 `channel_id + user_id` 为并发、每日额度和每周额度设置个人覆盖上限。
- 个人覆盖采用立即生效的绝对上限，实际有效值固定为 `max(渠道默认值, 当前有效个人覆盖值)`；不能借此降低用户上限，渠道默认值为不限时不提供“临时调高”。
- 不支持未来定时开始。覆盖记录可不设过期时间，表示持续有效直至人工撤销；设置 `expires_at` 后，到期自动回落到渠道默认值。
- 同一用户在同一渠道只保留一条覆盖记录，三个覆盖字段可独立留空，但共享一个 `expires_at`；三个字段均清空时等价于撤销该记录。
- 覆盖生效、撤销或过期都不取消在途请求、不修改用户钱包、订阅、Token 余额、消费日志、渠道历史 `used_quota` 或日/周已使用累计。
- 覆盖到期或撤销后，如果当前并发或周期已使用量已高于渠道默认值，只阻止后续新请求，等待并发自然释放或下个周期自动刷新。
- 覆盖必须持久化在 NewAPI 主数据库并兼容 SQLite、MySQL 和 PostgreSQL；运行时可以使用有明确失效机制的缓存，但数据库是唯一事实源。
- 管理 API 必须返回渠道默认值、当前有效值、覆盖值、过期时间和当前使用量；写操作记录管理员审计，但不得返回用户余额、Token、渠道密钥或存储内部信息。

### ai-fund / Cloudflare

- 延续现有 BFF 边界：浏览器只调用 ai-fund Worker，Worker 使用服务端管理员凭据调用 NewAPI，PAT 和渠道密钥不得进入浏览器、D1 或日志。
- CF D1 继续只保存号池渠道映射和本地审计，不复制 NewAPI 的有效限额、周期累计或覆盖状态，避免双写和过期状态漂移。
- 普通用户号池面板增加每周上限、本周已用、本周剩余与周刷新时间，并明确展示个人覆盖是否生效及到期时间。
- `/pools` 管理页面增加渠道每周金额上限和周额度活跃用户列表；`/admin` 增加独立“号池限制”页签，复用同一管理工作区管理 Claude/OpenAI 的渠道默认值、周期用量与个人覆盖。
- ai-fund 管理员可按 NewAPI 用户 ID、用户名或显示名搜索目标用户，不要求该用户已有请求记录；搜索、统一状态和覆盖数据均由 NewAPI 提供，D1 不复制用户限制索引。
- “调整已使用额度”和“临时调高上限”必须是两个明确分开的操作；前者修正周期计数，后者修改个人有效上限。
- Worker 只构造白名单字段调用 NewAPI；写成功后失效相关短缓存并写 D1 脱敏审计，审计失败不反转已成功的 NewAPI 操作。
- Claude/OpenAI 两个号池继续独立容错；单个号池或单项数据失败时，不清空另一个号池和现有账号观测。

### Compatibility And Safety

- 保持现有每日额度、并发接口和 ai-fund 当前调用契约兼容；新增字段应采用向后兼容响应扩展，避免破坏已在实施中的 `/root/project/ai-fund/.trellis/tasks/08-20-pool-user-limits`。
- 修改 `relaykit/` 稳定错误码时必须保持模块独立构建，并执行 `cd relaykit && GOWORK=off go build ./...`。
- NewAPI 实现遵循 build 分支定制隔离原则：新状态和核心逻辑放入独立文件，现有渠道选择、Relay 检查、正向记账和页面入口只保留最薄接入点。
- ai-fund 当前工作树已有 `08-20-pool-user-limits` 实现改动，后续调整必须在其现有代码上增量完成，不得覆盖或回退这些用户改动。

### NewAPI 管理端

- 渠道创建/编辑表单在现有并发、每日额度字段旁增加每周额度金额字段，并保持显式 `0`、金额换算和表单往返兼容。
- 现有 `ChannelUserLimitsDialog` 增加“每周额度”和“个人覆盖”视图；日/周/并发状态行同时展示渠道默认值、个人覆盖值、实际有效值和到期时间。
- 个人覆盖视图支持搜索用户、创建或更新覆盖、撤销覆盖；无 `ChannelOperate` 权限时写操作禁用且不可绕过。
- 创建个人覆盖不依赖该用户已有请求、额度或并发记录；管理员可按用户 ID、用户名或显示名提前搜索并配置，未产生使用时日/周已用和当前并发均按 `0` 展示。
- 日限、周限和并发活跃列表中的用户提供“临时调高”快捷入口，自动带入用户和当前状态；快捷入口只提升操作效率，不构成可配置用户范围。
- 所有新增用户可见文案使用 `t(...)`，通过脚本一次性写入 en、zh、zh-TW、fr、ja、ru、vi 七种 locale，并执行完整 i18n 同步与缺键扫描。

## Acceptance Criteria

- [ ] 渠道可配置单用户每周金额上限，`0` 表示不限；自然周按服务端时区周一 `00:00` 切换，日限与周限可同时生效。
- [ ] 每周累计覆盖普通 Relay、WebSocket、任务、Midjourney 和其他现有每日额度记账路径，且只记录最终实际渠道的一次正向结算。
- [ ] 达到日限或周限的新请求返回对应稳定 `429`，状态存储不可用时按现有契约返回 `503`；均不预扣、不访问上游、不重试、不禁用渠道。
- [ ] 管理员可查看和调整当前周已使用额度，调整不影响账务、日志、在途请求和其他周期状态。
- [ ] 管理员可为指定用户设置、查看和撤销并发、日限、周限个人覆盖；可选过期时间到达后无需定时任务即可自动回落。
- [ ] 从未产生请求记录的用户也能通过搜索提前配置覆盖；活跃列表快捷入口与搜索入口最终写入同一覆盖记录并返回一致状态。
- [ ] 覆盖生效时使用个人有效上限；撤销或过期后使用渠道默认值，超出回落后上限的在途请求不被取消，但新请求被阻止。
- [ ] 个人覆盖在应用重启、Redis 重连和多实例部署下仍以主数据库记录为准，缓存写后立即失效且不会长期返回过期值。
- [ ] NewAPI 管理接口只返回限制控制所需的最小用户字段和覆盖元数据，并记录不含敏感信息的管理员审计。
- [ ] NewAPI 渠道表单和用户限制 Dialog 可管理周限及个人覆盖，金额、显式零值、权限、分页、到期时间和七语言文案均正确。
- [ ] ai-fund 普通用户可查看日/周/并发的默认值、有效值、已用/当前值、剩余值、刷新时间和覆盖到期时间。
- [ ] ai-fund 管理员可调整渠道周限、当前周已用额度和个人覆盖；Worker 出站请求保持严格字段白名单，D1 只记录映射与脱敏审计。
- [ ] 现有每日额度、并发管理、号池观测和两个号池局部失败语义保持兼容；NewAPI 后端测试、relaykit 独立构建、ai-fund Worker 测试和前端构建均通过。

## Out Of Scope

- 不把个人覆盖扩展到用户钱包、订阅套餐、Token 独立额度、模型维度或分组维度。
- 不实现请求排队、严格额度预占、到期主动中断请求或跨周期退款回溯。
- 不让 CF Worker/D1 参与 Relay 请求热路径，也不在 NewAPI 与 D1 间双写限制状态。
- 不在本任务中重构现有每日额度或并发核心模块为通用插件框架。
