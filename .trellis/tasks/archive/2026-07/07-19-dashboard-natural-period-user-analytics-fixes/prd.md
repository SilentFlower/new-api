# 数据看板自然周期与用户统计修复

## Goal

在不替换新 UI 现有滚动时间快捷范围的前提下，为数据看板筛选器增加与旧 UI 一致的自然日历快捷查询，并修复用户统计筛选弹窗未翻译及“前 N 名”展示数量与用户预期不一致的问题。

## Background

- 新 UI 当前以 `TIME_RANGE_PRESETS` 提供 `1/7/14/29 天`滚动时间范围，模型统计和用户统计均依赖该配置；直接替换会改变现有行为并扩大后续上游同步冲突面。证据：`web/default/src/features/dashboard/constants.ts:46`、`web/default/src/features/dashboard/components/users/user-charts.tsx:212`。
- 旧 UI 的快捷查询是本地自然日历范围：今天、本周、上周、本月、上月；周以周一开始。证据：`web/classic/src/constants/dashboard.constants.js:46`、`web/classic/src/helpers/dashboard.jsx:98`。
- 用户统计筛选弹窗通过动态 `titleKey` / `descriptionKey` 传入英文键，但这些键未进入 locale 文件和动态键登记，因此中文环境回退显示英文。证据：`web/default/src/features/dashboard/index.tsx:288`，所有 locale 均缺少 `User Analytics Filters` 与对应描述。
- 用户排名先按当前查询结果中的用户名聚合，再执行 `slice(0, limit)`；产品语义已确认是“最多 N 个有消费记录的用户”，不足 N 时显示实际人数，不补零消费用户。证据：`web/default/src/features/dashboard/lib/charts.ts:753`、`web/default/src/features/dashboard/lib/charts.ts:763`、`model/dashboard_quota.go:84`。
- 当前排名图的左侧分类轴没有关闭 VChart 默认的标签采样，且图表容器固定为 `300/384px` 高；当排名条目较多时，VChart 会自动省略部分用户名标签，造成“选择前 20 但看起来只有约 13 名”的问题。证据：`web/default/src/features/dashboard/lib/charts.ts:838`、`web/default/src/features/dashboard/components/users/user-charts.tsx:286`、本地 VChart `base-axis.js` 默认令 `sampling` 为 true。

## Requirements

### R1. 新增独立的自然周期快捷查询

- 保留现有 `1/7/14/29 天`快捷范围及其滚动时间语义，不修改 `TIME_RANGE_PRESETS`。
- 在筛选弹窗中新增独立一栏“自然周期”，提供：今天、本周、上周、本月、上月。
- 自然周期按浏览器本地时间计算：
  - 今天：当天 `00:00:00` 至 `23:59:59`。
  - 本周/上周：周一至周日。
  - 本月/上月：自然月首日至末日。
- 选择自然周期时自动使用建议时间粒度：今天使用小时，本周/上周使用天，本月/上月使用周。
- 自然周期逻辑应独立放置，筛选弹窗只做最薄接入，避免重写现有滚动范围逻辑。
- 自然周期选中后继续支持自定义起止时间、时间粒度、用户名、分组和 API Key 筛选。
- 该能力应用于复用同一筛选弹窗的数据看板分区，包括模型统计、用户统计和流量分析。

### R2. 修复用户统计筛选弹窗英文文案

- `User Analytics Filters` 及描述必须在中文、英文、法文、日文、俄文、越南文和繁体中文下正确显示。
- 动态传入 `t(...)` 的键必须登记到 `static-keys.ts`，避免后续 i18n 扫描再次遗漏。
- 不改变模型统计和流量分析筛选弹窗现有文案。

### R3. 修复并澄清用户排名“前 N 名”展示

- 验证 `/api/data/users` 返回的唯一活跃用户数、`processUserChartData` 生成的排名数据条数和 VChart 实际渲染条数，区分数据不足与渲染裁切。
- 当当前筛选结果中唯一有消费用户数不少于 N 时，排名图必须实际展示 N 名，`5/10/20/50` 均按所选值生效。
- 排名图分类轴必须关闭会隐藏用户名的自动采样；在 20/50 名场景下保持每一名用户的标签和条形可辨识，不允许因固定高度、轴采样或裁切而静默少显示。
- 排名图按实际条目数分配稳定行高；内容超过卡片可视高度时使用卡片内部纵向滚动，不让前 20/50 名把整页和下方趋势图过度拉长。
- 当当前筛选结果中的有消费用户少于 N 时，显示全部实际活跃用户，并明确实际人数；不补充零消费用户。
- 用户趋势图继续只跟随排名选中的前 N 名用户，不改变消耗汇总口径。

### R4. 兼容性与质量

- 不修改 `/api/data/users` 现有查询参数契约或后端聚合口径。
- 新增自然周期计算和排名数量行为的确定性测试。
- 所有新增 UI 文案必须通过项目 i18n 脚本写入全部支持语言。
- 前端改动通过目标测试、类型检查、涉及文件 lint、格式检查和生产构建。

## Acceptance Criteria

- [ ] 现有 `1/7/14/29 天`快捷范围仍保留且行为不变。
- [ ] 筛选弹窗新增“自然周期”一栏，并可选择今天、本周、上周、本月、上月。
- [ ] 五个自然周期的本地时间边界与旧 UI 一致，周日场景仍正确以周一作为周起点。
- [ ] 自然周期分别联动到小时/天/周建议粒度，现有滚动范围的粒度联动保持不变。
- [ ] 选择自然周期并应用后，数据请求使用对应起止时间；重新打开弹窗时能正确反映已应用状态。
- [ ] 中文环境下用户统计筛选弹窗标题和描述不再显示英文，其他支持语言也有对应翻译。
- [ ] 当接口返回不少于 5/10/20/50 个唯一活跃用户时，选择对应“前 N”后排名数据和可见条目均为 N 个。
- [ ] 前 20/50 名在卡片内部可纵向滚动查看全部条目，用户名与条形保持可辨识，页面整体高度不会随 50 名无限增长。
- [ ] 当前筛选结果不足 N 个活跃用户时显示实际人数，不补零消费用户，且界面不造成“数据被截断”的误解。
- [ ] 用户趋势图与排名图使用同一前 N 用户集合。
- [ ] 相关测试、类型检查、lint、格式检查和构建全部通过。

## Out Of Scope

- 不重做整个数据看板布局或图表视觉风格。
- 不改变模型统计已有图表偏好中的默认滚动时间范围。
- 不为了补足排名数量而展示没有消费记录的系统用户。
