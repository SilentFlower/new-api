# Brief — 消息审计 AI 自动审核与总结

## Goal

- 在 Root-only 消息审计中增加推断会话级的手动 AI 审核与总结，并修复模型展示、失败原因、超大正文降级和失败请求归并问题，同时保持正文加密、日志隔离、保留期和正常 Relay 不受影响。

## Scope

- 系统设置配置一组全站固定的审核渠道、模型、上下文模式和 Tool 调用上限；默认上下文模式为服务端合并资料一次发送，Tool 模式保留为可选项；提示词、风险分类、输出结构和任务超时内置，不再设置独立的累计 Tool Token 或本地输入 Token 停止阈值。
- 只在推断会话详情中提供手动审核/重审，列表只展示审核状态、旧风险等级和待重审状态。
- 每个会话只保留最后一次成功结果；重审中或失败时保留旧结果，新结果成功后原子替换。
- 多次压缩会话以每个压缩断点的 `parent_request_id` 和触发时最新请求组成固定虚拟文件资料集。
- 默认模式下服务端把固定资料集合并为一次审核输入，并按已发送范围记录覆盖；可选 Tool 模式下 AI 通过受限 `list_files`、`read_file`、`search_files`、`search_files_regex` Tool 按需读取加密正文，正则检索仅在内存虚拟文件中使用 RE2 执行。
- 内部审核调用直接使用所选渠道 adaptor，不经过公开 Relay，不计费、不记录 Token/成本；调用会写入零额度渠道调用日志或错误日志用于排障，但不触发 `CaptureMessageAudit` / `FinalizeMessageAudit`，不会递归进入消息审计。
- 完整审核结果使用独立派生密钥加密；列表只保存风险、状态、模型、时间和新鲜度等无正文元数据。
- 原 1 MiB 超限策略改为优先保存有界的精简用户可见文本，真正 metadata-only 仍计算滚动 HMAC 和前缀指纹以支持 exact/prefix 会话归并。
- 失败请求继续进入审计并参与会话归并；列表和详情显示 HTTP 状态、稳定错误码和本地化安全说明，不保存或展示上游错误原文。
- 详情读取时按 Responses、Claude、Gemini 的载荷派生 Tool Call/Result 语义角色，修正协议外层 `user` 或缺失角色造成的误显；历史密文无需迁移。
- OpenAI 图片生成与图片编辑请求进入消息审计，只加密保存提示词和明确允许的安全参数；上传图片、mask、Base64、媒体 URL 原文和生成结果不保存，每次图片请求独立成一个审计会话。
- Default 列表不自动轮询；管理员通过页面刷新按钮按需获取 finalize 后的模型、状态和审核结果。
- 消息审计高频持久化改为请求内去重、批量解析 blob、批量写入引用，降低大上下文请求对 MySQL 的逐消息往返和唯一键冲突放大。
- 压缩会话候选先通过内容 HMAC 定位已有 blob ID，再按 `message_audit_items.blob_id` 反查候选请求，避免从历史请求及其全部消息项开始大范围关联扫描。
- 昂贵的存储统计采用有界时效缓存；列表和状态统计只在管理员手动刷新时重新请求。
- 清理请求时同步定向回收本批引用过且已无引用的 blob，避免清空后反复全表扫描孤儿 blob。
- 人工清空使用整表快速路径；MySQL 通过原子换表避免多实例写入在逐表清空间隙产生残缺引用，允许点击附近的新记录一并清除；定时保留期清理仍按批次执行。
- 审核来源随消息审计清理；执行中来源被清理时禁止重新写回过期摘要。

## Non-Goals

- 不单独采集当前请求的新模型响应正文、隐藏思考、流式增量或媒体二进制；客户端后续把模型回复作为历史再次提交时，该内容属于入站会话上下文并可被审核。
- 不对上传图片或生成图片执行视觉审核；图片协议的 AI 审核只覆盖已保存的提示词和安全参数。
- 不自动触发审核，不按单次请求分别生成结果。
- 不用 AI 结果自动封禁用户、停用令牌或拦截在线请求。
- 不把 AI 判断作为唯一合规结论。
- 不提供审核历史版本列表、列表快捷审核按钮或每次审核临时切换渠道/模型。
- 不允许审核调用访问外部网络、真实文件系统、任意数据库查询或其他会话；Tool 模式下 Tool 范围也必须固定在本次资料集内。

## Key Context

- 现有消息审计主链路位于 `model/message_audit.go`、`service/message_audit.go`、`controller/message_audit.go` 和 `web/default/src/features/message-audits/`。
- 正文只能进入主库独立加密审计表；普通日志、API 调用日志、ClickHouse 和管理审计不得包含正文、提示词或模型原始输出。AI 审核内部渠道日志只允许记录脱敏阶段、HTTP 状态、协议、任务和会话元数据。
- 新增 `message_audit_reviews` 和 `message_audit_review_sources`；完整结果加密，来源表只保存请求引用，不复制正文或密文。
- 通用系统任务需增加 scoped `active_key`，同会话幂等、不同会话排队，并继续通过任务类型锁全局串行审核。
- 每次任务固定目标请求和来源列表；任务期间的新请求只会让成功结果立即变为待重审。
- 最新虚拟文件正文不可用时拒绝审核；旧压缩来源不可用时必须明确反映未覆盖，不能伪装完整。
- 合并模式不注册审核 Tool，直接请求最终 JSON；Tool 模式的文件范围、游标、查询长度、单次返回、总调用轮数和任务超时由后端限制。
- Tool 调用次数在系统设置中按正整数配置并随任务冻结，默认 24，不设人为固定上限，仅在 Tool 模式生效；Tool 结果告知剩余调用和累计返回 Token，但累计 Token 只用于诊断，不再触发独立停止。模型真实上下文溢出由上游返回并归类为 `context_limit`。
- 审核任务保存不含正文、Tool 参数和模型输出的脱敏调用诊断，并在详情页 AI 审核区域展示渠道、模型、上下文模式、调用次数、Tool 次数、耗时、HTTP 状态和稳定失败阶段；原生请求启用并行 Tool 调用，文本 Tool 回退也支持一次返回多个 `tool_calls`。
- AI 审核详情区内联展示摘要、风险、服务端任务概览和诊断摘要；风险依据、读取覆盖、未覆盖来源和逐次调用诊断通过独立详情弹窗查看，长消息正文默认折叠并使用常驻可见滚动条。
- 已保存的完整入站会话上下文均可作为审计材料，包括客户端提交的 system、user、assistant 和 tool 角色；所有材料始终是不可信证据，不能覆盖审核系统提示词、扩大 Tool 范围或改变结构化输出契约。
- 设置页位于现有“日志维护 / 消息审计”区域，渠道与模型使用 Base UI 联动 Select，并遵守 `SelectGroup` 和受控值合同。
- 数据库与迁移必须同时兼容 SQLite、MySQL 5.7.8+、PostgreSQL 9.6+；历史新增字段使用可空语义避免把未知值显示为 0。
- 线上观测显示消息审计表在约 3 小时 39 分钟内增长约 505 MiB，当前逐条写入约产生每秒 76 次 blob/item 插入尝试和约每秒 6.7k 次相关行读取；优化必须降低数据库语句数量和历史扫描规模，而不是只提高 MySQL 连接数。

## Acceptance

- Root 可在会话详情触发、轮询和查看审核；非 Root 被拒绝，未配置或失效渠道/模型时明确提示前往设置。
- 同会话重复触发复用活动任务，不产生并发覆盖；不同会话按序排队。
- 列表可同时显示原高/中/低风险和“待重审”；重审失败不删除旧结果。
- 审核结果通过后端严格结构校验，展示摘要、风险、类别、依据、审核模型、时间、已读范围和未覆盖说明。
- 审核结果包含服务端计算的任务概览，包括来源数、可用来源、原消息数、虚拟分片数、已覆盖来源/消息/分片、未覆盖来源和估算 Token；拆分消息必须读完全部分片才算该原消息已覆盖。
- AI 只能读取本任务固定资料集，任何跨会话、真实路径、网络或任意数据库访问均被拒绝。
- 审核调用不新增消息审计、不扣减额度、不记录 Token/成本，也不影响 Relay、计费和原详情查看；仅新增零额度渠道调用日志或错误日志用于管理员排障，日志不得包含正文、Tool 参数、Tool 结果或模型输出。
- 默认合并模式一次发送已保存资料，Tool 模式通过有界虚拟分片和受限 Tool 按需读取；达到配置的 Tool 调用次数、任务超时或上游真实上下文窗口时明确失败，不会静默截断后声称完整审核。
- 超过原 1 MiB 的请求优先保留精简加密文本；最终 metadata-only 不保存正文但可按 exact/prefix 归并。
- 重复上下文继续复用同用户加密 blob，列表能区分原始大小、实际保留明文和新增密文载荷。
- 失败请求保留并参与归并，安全失败原因不泄露上游原文、密钥、URL 或正文。
- `/v1/images/generations`、`/v1/images/edits` 和兼容图片路由可在列表与详情中查看提示词审计记录；重复图片请求不会被归并成文本会话，媒体二进制和媒体地址原文不会进入审计表。
- finalize 后列表与详情的同一 `request_id` 最终显示相同模型。
- 详情将 Responses、Claude、Gemini 的纯 Tool Call/Result 展示为 `assistant/tool` 语义角色，不再错误堆入 `user`；原始协议载荷仍可在内容中核对。
- 单个请求内重复内容只解析和写入一次 blob，消息顺序与每条引用保持不变；跨请求重复内容继续复用同用户、同 schema 的既有 blob。
- 正常、exact、prefix、compressed、新会话等会话推断语义保持不变；compressed 候选查询以 blob ID 索引为入口，不再扫描不匹配的历史消息项。
- 存储统计缓存最多允许短时间陈旧，队列长度、运行状态和启停配置仍实时返回；清理或写入不因统计刷新而阻塞。
- 列表不会周期性变暗或禁用交互；管理员点击刷新后可看到 finalize、失败和审核结果的最新状态。
- 清理任一审核来源会删除对应结果；运行中任务不能在清理后回写过期摘要。
- 人工清空不会逐批扫描百万级消息引用，常规规模下应在数秒内完成；清理水位和当前清理任务自身保持有效。
- 后端定向、race、vet、全量测试及 Default 前端测试、i18n、typecheck、lint、build 和 `git diff --check` 通过；外部三库只在提供隔离 DSN 时声明实测。
