# 数据看板 Excel 导出增加分组列并优化性能

## Goal

为管理员数据看板的 Excel 报表补充分组维度，使汇总、模型明细和请求日志能够按实际请求分组核对；同时降低大数据量导出时的数据库重复扫描、Go 堆内存占用和 Excel 生成开销。

## Background

- 导出入口为 `GET /api/data/export`，由 `controller/usedata.go` 的 `ExportQuotaDataExcel` 生成三个 Sheet。
- `model.Log` 已有 `Group` 字段，历史请求日志可直接提供请求发生时的分组，不需要修改数据库结构。
- 当前 Sheet 1、Sheet 2 的聚合键不含分组，Sheet 3 也没有展示分组列。
- 当前一次导出会执行三条日志数据链路：Sheet 1 和 Sheet 2 分别分批扫描全部匹配日志进行 Go 侧聚合，Sheet 3 再一次性加载最多 500000 条日志。
- 当前使用 excelize 普通单元格写入模式，工作簿内容会随导出行数持续占用内存。
- 现有分组和 API Key 多选筛选参数必须继续作用于三个 Sheet，并兼容 SQLite、MySQL、PostgreSQL 以及独立 ClickHouse 日志库。

## Requirements

### R1：三个 Sheet 补充分组维度

- Sheet 1“汇总统计”增加“分组”列，并按“分组 + API Key + 所属用户”聚合，避免不同分组下的同名 API Key 数据混合。
- Sheet 2“模型明细”按“分组 + API Key + 所属用户 + 模型”聚合；分组标题和小计范围必须能明确区分分组。
- Sheet 3“请求日志”增加“分组”列，值取日志的 `group` 字段。
- 三个 Sheet 的表头、数据列位置和列宽同步调整，文件仍可被 Excel/WPS 正常打开。

### R2：保持统计与筛选语义

- 导出的时间范围、分组多选和 API Key 多选筛选条件继续同时作用于三个 Sheet。
- 汇总统计和模型明细继续使用包含 Anthropic 缓存读写 Token 的现有统计口径。
- 请求日志继续按时间升序输出，并保留输入 Token 缓存读写说明、输出 Token、额度、耗时、流式标记、渠道 ID 和请求 ID。
- 不修改现有路由、权限、文件名和前端下载交互。

### R3：优化大数据量导出

- 匹配日志只进行一次顺序遍历，在同一次遍历中完成汇总聚合、模型明细聚合和请求日志输出所需的数据处理。
- 请求日志不得再以最多 500000 个 `*Log` 对象一次性加载到 Go 内存。
- 保持现有导出上限语义：请求日志 Sheet 最多输出按时间升序排列的前 500000 条记录，超过部分不输出；不新增拒绝、截断提示或时间范围限制。
- Sheet 1 和 Sheet 2 继续基于完整匹配范围聚合，不受请求日志 Sheet 的 500000 行上限影响。
- Excel 数据行使用 excelize 流式写入能力，避免完整工作表单元格常驻 Go 堆内存。
- 数据库查询只选择导出和统计实际需要的字段，并在客户端断开或请求取消后停止后续处理。
- 保持现有准确统计口径，不以数据库原生 `sum(prompt_tokens + completion_tokens)` 替代包含缓存 Token 的 Go 侧计算。

### R4：错误处理与兼容性

- 查询、流式写入、刷新和响应输出任一步骤失败时不得返回伪成功文件。
- 新增或调整的查询必须兼容 SQLite、MySQL、PostgreSQL 和现有 ClickHouse 日志库路径。
- 不新增数据库字段或迁移。

## Acceptance Criteria

- [ ] Sheet 1 每一行都包含分组，且不同分组下的同名 API Key 不会合并。
- [ ] Sheet 2 的分组标题、模型数据和小计均归属于明确的“分组 + API Key”组合。
- [ ] Sheet 3 每条请求日志都包含日志记录时的分组。
- [ ] 三个 Sheet 使用完全一致的时间、分组和 API Key 筛选条件。
- [ ] Anthropic 缓存 Token 仍计入 Sheet 1、Sheet 2 的请求 Token 数。
- [ ] 大导出过程中不再构造最多 500000 条日志的内存切片，Excel 行通过流式写入生成。
- [ ] 单次导出只遍历一次匹配的消费日志数据。
- [ ] 请求日志 Sheet 仍最多包含按时间升序排列的前 500000 条记录，且不新增拒绝或截断提示。
- [ ] 即使匹配日志超过 500000 条，Sheet 1 和 Sheet 2 仍统计完整匹配范围。
- [ ] 客户端取消导出后，后端查询和生成流程能够停止。
- [ ] 导出的文件可由 Excel/WPS 正常打开，原有三个 Sheet、文件名和下载流程保持可用。
- [ ] 相关 Go 测试通过，并覆盖分组聚合隔离、筛选一致性和流式导出的关键行为。

## Out of Scope

- 普通用户导出权限。
- CSV 或其他导出格式。
- 异步导出任务、对象存储和下载历史。
- 修改数据看板前端筛选器或下载交互。
- 数据库结构及索引迁移；如实测证明索引是主要瓶颈，再单独评估。
