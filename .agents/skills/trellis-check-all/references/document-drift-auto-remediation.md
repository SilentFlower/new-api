# Document Drift Auto Remediation

本通道只处理低风险文档漂移。它不是普通问题自动修复授权，也不是改写需求、设计或验收标准的入口。

---

## `DOC-*` 模型

每个可自动修复的文档漂移使用固定字段：

| 字段 | 规则 |
| --- | --- |
| ID | 首次记录时依次分配 `DOC-001`、`DOC-002` |
| 类型 | `task-status`、`brief-stale`、`implementation-note`、`check-record`、`mechanical-link`、`fact-status` |
| 文件 | 需要修改的任务、规范、项目文档或本地上下文摘要路径 |
| 漂移 | 当前文档与实际 diff / 任务状态不一致的事实 |
| 证据 | `file:line`、命令输出或实际 diff 摘要 |
| 修复 | 精确说明要写入、更新或删除的内容 |
| 验证 | 修复后的静态检查、链接检查或重读确认 |

`DOC-*` 不占用 `CHK-*` 编号。自动修复失败或越界时，转成 `CHK-*` 或剩余风险。

---

## 允许自动修复

满足以下全部条件才可自动修复：

- 目标是任务执行文档、brief、check 记录、实现进度记录、机械链接、明显过期的本地上下文摘要，或项目文档中仅记录已验证事实状态的片段；
- 修复内容可由实际 diff、任务状态、命令输出或已存在任务材料唯一推出；
- 不新增需求、不改变验收标准、不改变设计取舍、不替用户选择产品语义；
- 不修改源码、配置、测试、迁移、生产数据或外部系统；
- 可自动修复性由具体片段语义决定，不由文档类别决定；同一文档中只有可由证据唯一推出的事实状态片段可改；
- 事实状态修复只允许同步状态、URL、版本号、配置键、命令结果、验证结论或时间点，不改操作步骤、责任边界、安全提示、协议字段或对外承诺；
- 改动小且可通过重读文件或简单静态检查验证；
- 用户没有明确要求本轮绝对只读。

典型例子：

- `brief.md` 漏掉本轮已经完成且可由 diff 证明的实现范围；
- `implement.md` 中机械状态仍写“待完成”，但对应步骤已经落地且无语义争议；
- `check.jsonl` 或任务记录中的文件路径、命令名、链接因重命名出现机械漂移；
- 文档写的检查深度、route 或状态与 runner / task.py 的确定性状态不一致。
- 任意 Markdown / HTML / 运行手册 / 接入说明仍写“待发布 / 待回读 / 旧版本 / 旧地址”，但已读取的发布记录、环境回读、测试输出或实际 diff 唯一证明目标状态已经变化。

---

## 禁止自动修复

以下情况必须进入 `CHK-*`、剩余风险或阻塞，不得自动改：

- PRD 需求、Acceptance Criteria、业务规则、UI 文案要求发生实质变更；
- design 的 API、数据模型、数据流、rollback 或 tradeoff 需要重新决策；
- 实现与规划冲突，无法判断是代码错还是文档错；
- 需要新增测试、改代码、改配置、改迁移或调用外部系统；
- 证据来自推测、聊天摘要或未读取的文件；
- 文档修复需要改写用户可见操作路径、接口协议、权限/安全边界、上线承诺、责任归属或验收口径；
- 修改会扩大任务范围或影响发布、权限、数据安全、生产行为。

---

## 写入时机

1. 先完成所有可继续的检查，收集 `CHK-*` 和 `DOC-*`。
2. 在最终报告前应用符合白名单的 `DOC-*` 修复。
3. 修复后执行对应验证，例如重读文件、检查链接、确认路径存在或运行无副作用的静态命令。
4. 报告中展示“自动修复”区，列出每个 `DOC-*` 的文件、修复内容和验证结果。
5. 若自动修复引入新的 diff，本轮报告的范围摘要必须包含这些文档改动。

subagent 模式只返回 `DOC-*` 候选；主会话按同一规则决定是否写入。validated auto-loop 模式由主会话完成允许的 `DOC-*` 修复后再 `record`。

### Validated Auto-Loop 绑定

- 只有当前任务的 `implement.md` 与 `brief.md` 参与 runner DOC 重绑；每个实际修改文件使用一次 `--doc-remediation-file <repository>::<path>`。
- 声明集合必须与 Check action 发出后的真实变化完全一致。`prd.md`、`design.md`、其它任务或其它文件一律不允许借此重绑。
- `check.jsonl` 可按本通道记录，但它不属于 planning/handoff hash，不传 `--doc-remediation-file`。
- record 返回 `status=retryable reason=artifact-drift` 时不运行 `next`；先撤回误改、补齐合法 DOC 声明后重录，或在无法安全归因时显式回写 `blocked + artifact-drift`。

---

## 失败处理

- 自动修复无法唯一确定：保留为 `CHK-*` 或剩余风险，等待用户确认。
- 自动修复验证失败：记录为 `CHK-*`，报告失败文件和验证命令。
- 自动修复后发现影响面扩大：停止继续自修，按普通问题模型报告。
